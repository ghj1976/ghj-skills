# 踩坑与实测数据

下面这些问题都真实导致过重做。数字来自“AI 查公园”项目，按数量级理解，不要当成固定常量。

## 1. 逐句克隆会换说话人

**现象：**“声音时好时不好”——上一句低沉平稳，下一句突然变亮变快，像换了一个人。

**实测：** 45 个独立生成的 beat，基频中位数从 **71Hz 到 154Hz**；同一 prompt/reference 生成的 4 个长段是 **100 / 103 / 100 / 98Hz**。长段之间很稳，逐句不稳定。

**原因：** 零样本克隆会在每次生成开始时重新采样说话人特征。文本短、标点不同，模型自由度更大。

**修法：** 生成 3–4 个长段（每段 30–60 秒），同一 prompt cache、同一 seed、`inference_timesteps=10`。不要逐句重生成。用 `librosa.pyin(fmin=60, fmax=350)` 测每段，超出 85–115Hz 就重生成。

## 2. 语速快、音调高会显得不可信

**现象：**“语速太快了，让人感觉不信任。”

**实测：** 第一版 **7.8 字/秒**（1667 字、217 秒口播），基频约 171Hz；最终版 **5.2–5.6 字/秒**，基频约 95–105Hz。

**修法：** 低音 prompt/reference，文本已知、语气平稳，目标 5.2–5.8 字/秒。个别句仍超过 7 字/秒，就对该 beat 做轻微 `atempo`（0.85–0.95），绝不做变调。不要给整条混音加 `atempo=0.8`，停顿会变得不自然。

## 3. 按句切长段音频会丢字

**现象：**“话没说完，就切成另外一个了。感觉丢了段声音。”

**实测：**“它连轴转了十一天”实际占 1.5 秒；逐句切分只给了 **1.08 秒**，因为它切在附近的 RMS 最低点，把最后约 0.5 秒切掉了。

**原因：** 能量最低点不一定是句尾；切完再拼接还会引入人为空隙，并可能把尾音挪到下一段开头。

**修法：** 长段音频绝不切。段与段之间留空隙，ASR 只用来定**时间**。口播保持连续，最坏情况是字幕早/晚一点，绝不会少一个字。

## 4. ASR 对齐：切点必须是下一句开口

**现象：** 画面/字幕已经切了，上一句还能听见；或者字幕先出现、声音后到。

**修法：** 每个 beat 找到第一个匹配上的转写词；边界取**下一个 beat 第一个词的开始时间**。这就是“下一句已经开口”。不要切在停顿中点，也不要只按字数比例（TTS 一快一慢就漂）。

**实测：** 第一段的 ASR 对齐边界是 `[0, 6.2, 8.54, 10.96, 13.9, 16.52, 20.6, 27.8, 32.74, 37.94]`。9.54 秒的切点正好是下一句开口；旧的 7.67 秒切点把句子切断了。

## 5. 把 48kHz 数组直接喂给 Whisper

**现象：** faster-whisper 对中文语音输出英文乱码（“I said I don't know how”），时间戳还超过音频时长。

**原因：** faster-whisper 对 numpy 输入默认按 16kHz 理解。48kHz 数组被当成 16kHz，等于慢放 3 倍。

**修法：** `librosa.resample(y, orig_sr=48000, target_sr=16000)` 之后再 `model.transcribe`。改完中文转写就正常了。

## 6. ctranslate2 找不到 cuBLAS

**现象：** `RuntimeError: Library cublas64_12.dll is not found or cannot be loaded`。

**修法：** 用 CPU 跑 faster-whisper（`device="cpu", compute_type="int8"`）；3 分钟中文口播一两分钟就能对齐。也可以把 torch 的 `lib` 目录加进 PATH，但 CPU 更省事。

## 7. 图片切换时卡顿/冻结

最终版之前有四个叠加原因：

1. **停顿期间推拉被 clamp。** `progress = min(1, lt / beat_duration)`，而 0.34 秒空隙里 `lt` 超过了 beat 时长，画面冻结 0.34 秒，然后下一镜头突然跳。修法：用 `next_beat.start - start` 作为视觉时长，**线性**推进，切点前不 clamp。
2. **smoothstep 缓动。** `smoothstep` 在 t=0 和 t=1 速度为 0，每个镜头首尾都会近乎静止。修法：线性，或尾速度不为 0 的 ease-out。
3. **整数裁切。** `int(2048/zoom)` 每 2–3 帧才变一次，然后跳 1px。修法：`Image.transform(..., AFFINE, (sx,0,x0,0,sy,y0))`，用浮点值。
4. **叠化双影。** 两行大字或两张插画叠 0.2–0.3 秒，看起来像渲染故障。修法：硬切，用 whoosh 盖住。

**验证：** 解码 MP4，在切点附近取 36 帧，缩到 270×480 后算平均绝对差。修之前有 9–14 帧 diff <0.02（肉眼一样），随后一个 26–74 的尖峰；修之后 0 个冻结帧。

## 8. 静止文字卡被编码成冻结帧

即使整帧缓慢推近，18 秒场景只放大 7.5%，平均每帧约 0.004%，经常低于编码器更新阈值。文字卡于是会静止好几秒。

**修法：** 文字/数据版式加整帧缓慢推近 + 低透明度移动光扫。验收要看**解码后**的帧，不要看源帧。

## 9. 下划线穿过字形

**现象：** 橙色线从“一把钥匙”“自己想办法”的底部笔画中间穿过去。

**原因：** 中文字形墨迹会超出 em 框，`y + font_size + 22` 并不在字形下方。

**修法：**

```python
bbox = d.textbbox((x, y), text, font=f)
line_y = bbox[3] + 16
d.rectangle([x, line_y, x + width, line_y + 8], fill=accent)
```

**同族问题（第二轮返工）：小标签的下划线贴字。** 卡片左上角的 eyebrow（27px）、
文字卡引语上方的小标签（28px）、数据卡的说明标签（32px）原来都写死了一个绝对 y
（`top + 42`、`y + 42`），而 32px 中文字形的墨迹下缘刚好就是 `top + 42`——线紧贴“年”的底边，
只剩 0–4px，缩到手机上看就像字被划了一道。三个版式统一改成 `draw_eyebrow()`：

```python
def draw_eyebrow(d, x, y, text, size, color, ac, gap=13, upper=False):
    t = text.upper() if upper else text
    f = font(size, False)
    d.text((x, y), t, font=f, fill=color)
    bb = d.textbbox((x, y), t, font=f)
    ly = bb[3] + gap
    d.rectangle([x, ly, x + 36, ly + 4], fill=ac)
```

数据卡的 `eye_h` 同步从 48 加到 60，保证线和主数字之间还有 10px 以上。
验收方法：把 1080×1920 缩到 480 宽看，线还能和字分开才算过。

## 10. 音效削波与响度漂移

音效轨按 RMS 0.02 归一，峰值仍然到 **1.0**，混音直接削波。修法：音效按**峰值**归一到 0.30，`amix` 后加 `alimiter=limit=0.95`，再用 `ebur128` 查真峰值。目标 −16 LUFS，峰值 ≤ −1.5dB。

## 11. CPU 版 PyTorch 看起来像 VoxCPM 的 bug

系统 Python 装的是 `torch 2.14.1+cpu`。VoxCPM 能跑，但 30 秒音频要 20 多分钟（约 40 倍实时），工具调用直接超时。这不是 VoxCPM 的问题。用 `--system-site-packages` 建 venv，补装 `torch/torchaudio +cu128`，桌面 GPU 上生成速度大约回到实时×0.3–2。

## 12. 导出的文章图片链接通常是坏的

Markdown 里常见 `assets/<标题>/file-*.png`，实际图片在文章目录。按**文章出现顺序**映射，然后逐张打开确认和段落对得上。不要只看文件名，也不要悄悄丢掉一张图。

## 13. 16:9 还是 9:16

第一版 16:9 在手机上被否。手机平台默认 1080×1920；16:9 只用于文章内嵌播放器或用户明确要求。旧版本单独放一个目录——用户明确说要并排对比。

## 14. 用户说“声音不符合预期”，但你也听不到

被否的第一版是低沉男声（基频 105Hz），用户要求换成另一条视频（`02/q1.mp4`）里的解说音色。问题在于：没法试听，只能靠量化指标判断“像不像”。

**做法：**

1. **从源视频抽音轨**，按 whisper 词级时间戳选 4–8 秒连续说话的片段，边界落在词的起止处（不切在字中间）。
2. **参考音频带 BGM 必须先去噪**。q1 的口播全程压着背景音乐，音节间隙的 RMS 只到 −17dB（干净人声应该在 −50dB 以下）。用 VoxCPM2 自带的 ZIP-Enhancer（ModelScope `iic/speech_zipenhancer_ans_multiloss_16k_base`）处理 prompt 和 reference，输出 16kHz，再峰值归一到 0.9。
   - 坑：本机 torchaudio 2.11 走 torchcodec，缺 shared FFmpeg DLL，`torchaudio.load` 直接抛 `libtorchcodec_core4.dll` 找不到。Gyan 的 ffmpeg 是静态编译，没有 DLL 可补。**修法**：`torchaudio.load/save` 换成 soundfile 实现（见 `make_voice_ref.py`），模型照常跑。
3. **量化验收**（`check_voice.py`）：段间基频极差 ≤25Hz、每段与参考的 LTAS 相关 ≥0.90、语速 4.5–6.5 字/秒。

**实测（q1 女声）：** prompt 基频 238.6Hz、reference 245.6Hz；四段生成 251.4 / 242.8 / 225.2 / 230.5Hz；LTAS 相关 0.978–0.990；旧的男声版与 q1 的 LTAS 相关只有 0.055——数值上能立刻区分“换对了”还是“还是那个人”。

**别硬套男声阈值。** 主流经验值“基频 85–115Hz”只适用于低沉男声；女声 225–251Hz 才是正常。判断标准应该是**段间稳定 + 与参考同音区 + 频谱相似**，不是绝对频段。

**语速要单独看。** q1 本身是短视频快节奏（6.4–6.9 字/秒），统一 0.92 倍 `atempo`（不变调）后落到 5.7–6.1 字/秒；`voice.json` 里的 `atempo` 由 `tts_chunks.py` 自动套用，原始长段存 `*_raw.wav`。不要把单个音色的问题用逐句变速去补。

## 15. 帧差单位搞错，会把正常慢镜头判成冻结

`qa_video.py` 早期版本这样算：

```python
a = np.asarray(Image.open(f).resize((270, 480)), dtype=np.float32)
d = np.mean(np.abs(a - prev))          # 0–255 尺度！
if d < 0.02: frozen()                  # 等价于 0.00008 归一化
```

阈值 0.02 看着像“5 个灰度级”，实际是 **0.02 个灰度级**。慢推拉在 270×480 上每帧只变 0.01–0.05 个灰度级，于是被反复判成冻结；而真正被否的版本里，冻结段的 diff 是 **0**。

**修法：** 帧差除以 255 归一化，冻结判据改成“连续 ≥3 帧完全相同（diff = 0）”，并把 `min_diff` 用 5 位小数打印出来。要更硬的证据，再用全分辨率逐帧比对：`identical_pairs` 必须是 0。

**教训：** 质检阈值要么有单位注释，要么直接引用归一化后的物理量；否则“通过/不通过”只是巧合。

## 16. “每节开头声音卡一下”——段首瞬态 + 长停顿叠在章节切换点

**现象：** 用户反馈“开头卡顿一下，每节时都卡顿一下，然后正常播放”，画面没问题，是声音。

**排查：** 把 `audio_mix.wav` 按 20ms 算包络，发现每段配音的**开头**都有一串固定形状：

```
-11 -18 -35 -47 -56 ...（约 40ms 的咔哒）→ 静音 0.3–0.4s → 正常说话
```

四个长段的瞬态完全一样，说明是 VoxCPM2 生成时的起手音。`build_audio_cont.py` 按 −45dB 裁首尾静音，
这段咔哒（−11dB）高于阈值，被当成“语音起点”保留了下来。而长段拼接点（每 2 个场景一段）
正好落在章节边界，于是每一节开头都是“咔—静半拍—再说”。

同一批音频里还有 0.9–1.0s 的句间长停顿（76 处 ≥0.12s 的静音，其中不少 0.5s+），听起来也像卡住。

**修法：** 新增 `clean_audio.py`（在 `tts_chunks.py` 之后、`align_asr.py` 之前跑）：

1. 先用 atempo 统一语速；
2. 用“连续 200ms 高于 −38dB”判定真正开口，裁掉段首 40ms 瞬态和其后静音（咔哒只有 60–80ms，不会通过 200ms 判定）；
3. 把 ≥0.55s 的静音压到 0.45s，拼接处 10ms 淡入淡出；
4. `build_audio_cont.py` 的段间空白从 0.65 收到 0.55。

修完实测：段首从 −11dB 起变成 −77 → −36 → −27 的自然起音；章节起点 ±80ms 内最大样本跳变 0.03–0.07（正常），没有咔哒；最长静音 0.42s。

**教训：** 拼接点要和章节切换点对齐，但拼接点上的“段首伪影”必须清掉——否则观众听到的是每一节都卡一下，还以为是画面问题。

## 17. 开头“刺啦”一声，以及段与段之间的音色漂移

**刺啦**：`sfx_track()` 在第一秒内放了两个噪声类音效（0.04s 的 impact、0.86s 的 whoosh），
而音乐从 0 秒才淡入到 −63dB。噪声冲击叠在淡入上，听起来就是开头一声“刺啦”。
修法：开头不放音效，让音乐淡入后直接开口；章节转场的 whoosh 保留但降到 0.45。

**音色漂移**：同一 prompt cache 生成 6 个场景 / 3 段时，出现过 263 / 248 / 224Hz（极差 39Hz）。
`check_voice.py` 会判 FAIL。不要用变调硬拉——换随机种子重生成偏差最大的段即可
（`regen_chunk.py 0,2 --seeds 20,21,22`，按基频接近参考 + LTAS 最高挑），实测收到 239 / 249 / 240Hz，
极差 9.8Hz。同一段不同种子的基频差异可达 40Hz，这是 VoxCPM2 长段生成的正常方差，不是参数错。

## 18. “太跳跃”与“信息量太大”，是同一个问题的两种表现

同一篇文章被否了三次：

1. 45 个短句版：每句一个结论，句间没有承接 → “内容太跳跃”。
2. 按段落重写后 54 个镜头、1196 字：句子连起来了，但塞了 5 条线 → “信息量太大，都没说透”。
3. 只讲一条线、34 个镜头、823 字：每段给足定义+对照+解释 → 通过。

**规则：** 一条主线讲透 > 五条线各说一句。判断标准是“这条线能不能给出定义、证据、反例各一句”；
给不出来就别放。删掉的行业跟进、三个自测问题、能力分层，在 2 分钟里只能一句带过，就是噪音。

## 19. 配图不是“有图就行”，是“这句和这张图对不对得上”

第一版按场景套默认图：6 万人名单配天平、现金牛配天平、问题一配资本流向图。用户一眼看出“图不对文”。

**做法：**
1. `script_data.py` 里用 `BEAT_IMG` 逐 beat 指定，`""` 表示不配图；
2. 图上自带中文标题时，先读标题再决定——标题和这句语义相反就不能用（“过去能顶四五年” vs “工具贬值快于人成长”）；
3. 30 多个镜头里有一半是数据/文字卡很正常；
4. 生成 `配图对照.png`（`contact_sheet.py`）逐镜头扫一遍，比在时间轴上拖动快得多。

**别名坑：** 按 beat 编号写映射时先数准每个场景有几个 beat（本轮按 9 个规划、实际 8 个，
导致“第三重”配到天平、“现金牛”配到三重交集）。写完 `print` 一遍 timeline 里的 `id/img` 再渲染。

## 20. 从参考视频剪 B-roll：三个错，一次白渲染

背景：文章没有配图，只有一条英文原片。第一版用 14 张抽帧（上场 10 张），能做但“像 PPT”；
第二版把 6 个镜头换成原片的静音片段，重渲染 24 分钟。

1. **缩略图序号 ≠ 真实秒数。** 按 1fps 缩略图的“第 26 秒”选了 `26.20–29.00`，以为是指尖捏着标签，
   实际是研究员对着镜头说话——缩略图标签与真实时间差了半拍，而原片在这个位置 25.60s 就切了镜头。
   **修法：** `video_sheet.py` 用 `-ss` 精确抽帧 + ffmpeg 场景检测，直接打印镜头区间；
   每个候选片段先抽 1 帧肉眼确认内容，再写进 `CLIP_SRC`。
2. **片段循环或停在末帧。** 素材 2.5 秒、beat 2.74 秒：循环会跳一下，停在末帧会被编码器判成冻结。
   **修法：** 按 beat 进度映射 `idx = lt / duration * frames`，素材短就整体放慢（本轮 0.77–1.0×）。
3. **片段镜头又叠整帧推近。** 整帧 5% 推近会把 1080 卡片的左右边缘各裁掉约 27px，
   原片右上角的 Virginia Tech 水印被切掉。**修法：** 片段镜头跳过 `slow_zoom`，运动交给素材本身。

**实测运动量（解码后两帧平均绝对差）：** 片段内隔 0.6–1.2 秒取帧是 **0.008–0.041**；
同一支片子里最慢的静帧镜头，35 帧内最小差只有 **0.0016**。片段的“动”高一个数量级，
所以 `qa_video.py` 的冻结判据（diff=0）不会误判，但也别用 0.02 这种阈值去卡片段。

**内容配比：** 56 个镜头里 31 个有画面（其中 6 个动态）、25 个数据/文字卡。
动态镜头别超过 1/4，否则每两三句就切回文字卡，节奏反而碎。

## 21. 白底图、数据卡数字、标题幽灵、结尾卡：四个很显眼的小坑

- **白底照片铺底发灰。** 固定 `alpha=150` 时，mean≈200 的白背景压完约 110（中灰），
  标题区对比度掉一半，字幕也像蒙了一层雾。改成按底图亮度自适应：
  `alpha = clamp(150 + (mean - 55) * 1.15, 150, 215)`，白底直接到 215。
- **数据卡 count-up 太长。** 1.1 秒动画放在 1.18 秒的镜头上，观众九成时间看到 `0.3 克`
  （目标 `0.5 克`）。压到 0.55 秒；`25–28%`、`1/4` 这类带数字后缀的别名不要参与 count-up。
- **标题幽灵数字贴边。** `"0.5g"` 在 230px 时右边缘被裁；字号改成按 `getlength ≤ 640` 自动缩。
- **结尾卡永远不出现。** `build_audio_cont` 把最后一个 beat 的 `end` 设成总时长，
  `t > last["end"]` 永远不成立（旧版一直没发现，因为结尾画面本身也说得过去）。
  改用 `timeline["speech_end"]` 触发，正好把 2.2 秒尾巴留给来源 / 互动引导。

## 22. WSL 调 Windows Python：环境变量不透传

在 WSL 里写 `VIDEO_OUT=xxx.mp4 python.exe render.py`，渲染脚本收不到 `VIDEO_OUT`，
24 分钟的成片写进了默认文件名；`ASSET_DIR` 同理不可靠。Win32 进程默认只拿 `WSLENV`
白名单里的变量。

**修法：** 改脚本里的默认值（比如 `VIDEO_OUT` 默认文件名）最稳；图片目录用
`render.py --assets <dir>` 参数传，不要指望环境变量。脚本从 WSL 调 Windows ffmpeg 时，
输出路径必须用 `wslpath -w` 转成 `D:\\...`，否则 ffmpeg 会报 “Could not open file”。

## 23. 开头不知道要讲啥：缺的是主题句，不是信息

**现象：**“感觉有点乱，开头相当部分不知道要讲啥？讲的主题不突出。”

**实测（100 亿项目）：**
- v1：68 个 beat、1721 字、4:53。开头 18 秒只给了“100 亿”和“钱转一圈”，
  接着 36 秒讲三层关系，中段又单独用 34 秒回答“AI 到底赚不赚钱”。
  每一段单看都对，但观众不知道这条视频要论证什么。
- v2：65 个 beat、1668 字、4:52。前 17 秒先给结论 + 路线图：
  “100 亿 → 但这不是利润，是一张正在滚动的账单 → 只看三件事：
  这是什么钱、谁在付、它什么时候会停。” 章节标题连起来就是叙事线，
  “卖铲子”整章砍到只剩一句注脚。同样的时长，主线清楚了。

**原因：** 写作顺序是“按文章顺序覆盖”，而不是“先定主题再选证据”。
背景被当成必须讲完的前置，支线因为“原文写得好”而保留，于是开头全是铺垫。

**第三轮（人物片）：主题句有了，还是离散。**

前一条片子（Bellard 人物片）主题句写的是「他写了半个互联网，却把名字藏了起来」，
三件事也列了：他写了什么 / 他为什么躲 / 谁在替他挨打。观众反馈仍然是
“整个视频没有主题，三个方面太离散了，听的有点发懵”。

原因不是没写主题句，而是**把三个并列的人物侧写当成了论证**：
- 主题句是对事实的描述，主角是“他”，观众既没有代价也没有收益；
- 三个问题彼此独立，每章都能单独成篇，用“所以”串不起来；
- 素材按“原文有哪几段”来选，而不是按“它证明哪一半”来选。

重做时只留一句判断：「他写了半个互联网，但养它的人不是他。」——反常识、有代价
（有人拿命填）、观众带走的是“你用的免费基座，账单落在维护者身上”。三问随即变成因果链：
基座有多大（所以账单很大）→ 他为什么先跑（所以账单转手）→ 落在谁头上（所以有人拿命去填）。
π 的对比数字、反社交细节、Amarisoft 的来历全部压成一个镜头或删掉。

**修法：**
1. 先写**突破点**（不是主题句）：一句反常识的判断 + 观众的代价，25 字内，写进 `script_data.THESIS`。
2. 过四问：反常识吗 / 有代价吗 / 观众会因此改变什么 / 25 字内能说完吗。答不上来就别开写。
3. 三问改成三个**后果**，每一问由上一问逼出来；章节 `label` 用“所以 / 但是”能串成一句话。
4. 换题测试：把文章换成同主题另一篇，这套结构还成立 → 你在套模板。
5. 删章测试：删掉后突破点仍成立 → 支线，砍掉或压成一个镜头。
6. 每条素材先回答“它证明了突破点的哪一半”，答不上来不进片。
7. 开头 15–20 秒：钩子事实 → 突破点 → “只看三件事” → 第一问。

**判据：** 只看前 20 秒，能否说出“这条视频要论证什么、接下来回答哪三个问题”；三个小标题能不能用“所以”串起来。
说不出来，先改结构，不要先调语速和画面。

## 24. 配图“两边空白”：量了才知道该裁哪边，裁成什么样

**现象：** 用户指着收尾那张图说“这个图两边是空白，视频中截图中间部分来放”。

**实测（06 那篇 40% 文案）：** 9 张素材里 8 张的内容占 84–100% 宽，只有一张不同——
`file-…102021337.png`（1024×572）的插画只占中间 **38.5% 宽**（x315–708），
左右各约 31% 是纯米色 `(249,246,237)`。放进 1080×608 的卡片，插画只有 **416px** 宽，
屏幕上就是“一张纸上画了个小人”。

**但不能见白就裁。** 16:9 插画四周那点边是构图的一部分，裁完贴边反而难看；
4:1 横幅（1536×383）本来就没空白，真正的问题是高度只有 270px。

**量法：** 四角取中位色当背景，`|pixel - bg|.max() > 12` 得墨迹掩膜，
再用“整列墨迹 > 2% 高 / 整行墨迹 > 0.5% 宽”求 bbox——单像素杂点撑不大 bbox。
透明 PNG 直接走 alpha 通道。`image_margins.py` 干这件事。

**判据（内容占比 → 处理）：**

| 实测 | 判断 | 处理 |
|---|---|---|
| 宽高比 ≥ 2.2（横幅 4.01） | 超宽 | 不裁，`card` 走深色卡底（gap > 0.28h） |
| 横竖都 ≥ 80%（84% / 89% / 95% / 100%） | 空白不多 | 不裁，用原图 |
| 宽 38% + 裁完 0.72 比例 | 纸上的小人 | 裁到内容 + `poster` 竖卡（582×800） |

**两个连带坑：**

1. **`poster` 卡别贴字幕。** 卡片 `y=540, h=800`，底边 1340，字幕区从 1440 起——
   h 试过 858，卡底 1393，字幕几乎贴着卡边，像和卡片连成一块；800 是舒服的点。
2. **`poster` 卡别加顶部强调条。** 大标题下划线在 y≈512，卡顶在 540，再画一条 4px 的橙色条，
   和标题下划线只差 18px，看着像“两条线”。
3. **别用“放大”代替“裁切”。** 想把两侧空白挤出画面就得放大 2.6 倍，插画反而糊；
   裁掉空白 + 换竖卡，同样的画面高度能多出 40% 的插画宽度（416 → 582px）。

**修法：** `python image_margins.py ../06` 看报告 → `--crop` 生成 `assets/<name>_crop.png`
→ beat 里写 `poster` 或 `card` + 衍生文件名。`render.py` 的 `asset_path()` 会先找
`--assets` 目录、再回落项目 `assets/`，所以原素材一张都不用动。

## 25. “格式太单调”：不是内容问题，是版式问题

**现象：** 用户说“技能文章生成视频的格式太单调了”。片子信息没变，但 40 个镜头是
`配图卡 → 大字卡 → 数据卡 → 配图卡` 的循环，观众 30 秒就摸清规律，后面讲什么都像在等下一张图。

**原因：** 只有 `card` / `text` / `data` / `hook` 四种版式，而四种都长成“上面大字、下面一张卡”。
真正的问题是**叙事类型没有被画出来**：分层的、分步的、两边对比的、谁跟谁说话的东西，
全都塞进同一张图片卡。

**修法：** `render.py` 增加 9 种结构版式，数据写在 beat 元组第 10 位 `extras`：
`chat`（消息流）/ `layers`（分层）/ `flow`（步骤）/ `compare`（左右对比）/
`bars`（条形）/ `kpi`（多个数字）/ `list`（清单）/ `terminal`（日志/PR）/ `quote`（长引语）。

**硬指标（本项目 40 个 beat 实测）：** 12 种版式、同版式不连续、`text` ≤20%、
每 15–20 秒换一次类型。信息量一个字没加，观感完全不同。

**四个连带坑（都在这一版踩过）：**

1. **中英混排被拆词。** 逐字换行会让“Agent”变成“A / gent”。`wrap_cjk()` 先把
   `[A-Za-z0-9_.%+-]` 连续段切成不可分割的 token，再按像素贪心换行；
   行首标点（，。）提到上一行末。
2. **`quote` 孤字成行。** 用“单行塞进 860px”缩字号，会在 `min_size` 卡住，最后一行只剩“。”。
   改成按“最多 3 行 + 末行 ≥3 字”反推字号。
3. **`chat` 名字行被标题条压住。** 气泡上方的名字行有 34px，舞台起点要再低 40px，
   可用高度同步减 34。
4. **结构版式的大字压到面板。** 结构版式的面板从 y=536 起，大字基线要从 292 上移到 262，
   推近降到 2.2%，`big` 压到 3–6 字。

**还有一个“时长”坑：** `bars` 这种需要生长的版式，如果口播只给 1.08 秒（“结果是这样。”），
条还没长完镜头就切了。数据版式的口播至少给 4–7 秒，把那几个数字念出来——
这既要改文案，也要重新生成那一段 TTS（本次为此单独重跑了 chunk 1）。

## 26. ASR 词起点偏早：切点在句中，尾音被吞

**现象：** 字幕/画面比声音早半拍切走，尤其是短句后面接长句时。

**实测：** 一句 1.66 秒的镜头，能量图显示切点（6.10s）落在“抱 怨”中间，
真正的停顿在 6.42–6.90s，下一句 6.96s 才开口。whisper 给“十”的时间是 6.10，
偏早 0.86 秒；`snap_to_onsets` 只吸 ±0.55 秒，够不着。

**修法：** `snap_forward_to_pause()`：切点之后若紧跟一段 ≥0.12s 的静音，
就把切点放到静音结束 +0.03s。只往后挪、最多 1 秒，已经落在开口上的不动。
同类改进：章节边界不要取两段中点（长段之间有 0.65s 空白），直接取新章节第一句的开口。

## 27. 音色“跟之前几条片子不一样”：段间基频漂移 + 叠加 atempo

**现象：** 用户看完第一版说“声音感觉不对，跟之前生成的几个声音不一样了”。
不是听不出问题的那种“说不上来”，是**一耳朵**——尤其开头。

**实测（NICAM 项目，q1 音色，参考音 238.6Hz）：**

| 版本 | 4 段 raw 基频 | 处理方式 | 成片语速 | 用户反馈 |
|---|---|---|---|---|
| 第一版 | **261.7 / 251.4 / 249.9 / 238.6Hz** | 0.78 统一 + 第 0 段再补 0.91 | 5.27–6.14 | 声音不对 |
| 第二版 | 240.0 / 237.2 / 245.6 / 240.0Hz | `TEMPO_MAP` 逐段一次（0.744–0.855） | 5.58–5.63 | 对上了 |

**为什么旧门禁没拦住：** `check_voice.py` 当时是“参考音 ±18% + 段间极差 ≤30Hz”。
261.7Hz 相对 238.6Hz 只高 9.7%，段间极差 23.1Hz，两项都在门里——`PASS`。
但听感上，第一段的音区已经比其余三段高出一个“人”的距离。

**两个原因叠加：**

1. **采样种子带来的音色漂移。** 同一 prompt cache、同一文本，换 seed 生成 4 次，
   基频能差 15–25Hz。第一版四段都用了 seed 20，没人检查；第二版每段 4 个种子
   （20–23）各生成一次、按参考音挑，才收到 9.6Hz 的极差。
2. **叠加 atempo。** 第一版为了让第 0 段跟其余段拉齐，在 0.78 之后又补了一次 0.91
   （合起来 0.71）。两次 WSOLA 会让声音发闷、齿音变糊，听感就是“换了个人的开头”。
   第二版改成 `TEMPO_MAP`：每段从 `*_raw.wav` 一次 atempo 到位。

**修法（已写进脚本）：**

- `regen_chunk2.py`：每段 4 个种子，候选落 `audio/cand/`，按 `|f0-参考f0| + LTAS` 挑；
  谱心（centroid）默认不参与打分——它随文本内容能差 800Hz，拿它当目标容易挑错。
- `check_voice.py`：门禁收紧到**参考音 ±8%、段间极差 ≤18Hz、MFCC ≥0.985**，
  并支持 `--baseline 上一版/audio`：系列视频最有效的判据是“跟上一版像不像”
  （MFCC ≥0.99 是硬门槛；Δf0 只作参考，不同文稿能差 20Hz）。
- `clean_audio.py`：支持 `TEMPO_MAP`；atempo <0.80 或没有 `*_raw.wav`（会叠加）时打印 WARN。

**教训：** `check_voice` PASS 只代表“在参考音的音区里”，不代表“跟上一版是同一个人”。
系列视频必须和上一版对比，且**一条片子只做一次 atempo**。

## 28. 中文数字被转写成阿拉伯数字：切点落进句中

**现象：** 02 章的“对应六千零七条 Claude Code 助手消息”只有 1.58 秒画面，
上一句字幕还停在屏幕上——典型的“话没说完就切”。

**实测：** Whisper 把“六千零七”转写成 `6007`、把“五千五百八十九”转写成 `5589`。
`difflib` 匹配时跳过这几个字，`first[beat]` 落到后面的英文词 `Claude` 上（本地 8.28s），
而真实开口在 6.78s（6.42–6.98 是一段静音）。切点晚了 1.3 秒。

**两个错误修法（都试过）：**

1. **按字数估位置。** `14 万行 Fortran` 42 个字符、实际只有约 30 个音节；
   估计值 7.50s，把本来正确的 6.14s 推到 7.87s，反而切在句中。英数混排一多，字数就不可信。
2. **只往后找静音。** 切点落在语音里时，往后 1.5s 内最近的静音结束可能是**这一句的结尾**，
   挪过去等于把这句压成 0.8 秒（实测 02_02 变成 8.99–9.80）。

**正确做法（`fix_boundaries.py`）：** 只问“切点是否落在静音里”。
在静音段内（±0.12s）就不动；落在语音里才往后找最近的静音结束（≤1.5s），
并限制“不越过下一个切点 0.3s”。改完看 0.1s 能量包络复核：
02_01 止于 6.45、02_02 开口 6.78、02_03 开口 10.20。

**预防：** 口播里的关键数字优先写阿拉伯数字（`6007 条`），TTS 会读成“六千零七”，
ASR 也回 `6007`，字符匹配就不会跳过；仍然错位时用 `fix_boundaries.py --dry` 先看。

## 29. 开头 3 秒是静态大字卡：观众直接划走

**现象：** 一条 2:34 的片子，第一版开头是「你从素材网站下载的 3D 模型，其实是一张冻结的网格」——
一句好钩子，配一张深色大字卡，没有任何画面。反馈是「开头不吸引人，直接就划走了」。
改完之后同一句旁的文稿、同样的时长，观感完全不同。

**原因：** 观众判断“要不要继续看”只发生在前 3 秒，判据是**画面**，不是文案。
文字卡在第一帧给不出“这是什么、有多猛”，只给出一句需要读的话。

**改法（v2 实测）：** 把文稿里最炸的两段素材提到最前面，四拍走完：

| 拍 | 画面 | 文稿 |
|---|---|---|
| 0–4s | 2,660 个模型铺满卡片，官方计数器 1,223 → 2,600+ | 「两千六百多个 3D 模型，全部免费，而且每一个都能改」 |
| 4–9s | 警长换装（竖屏整帧设备卡） | 「换件外套、换个配色，拖一下，模型自己重新贴合」 |
| 9–13s | 冻结网格 vs 可调程序 | 「以前要高不可攀的 3D 资产，现在变成了拖滑块」 |
| 13–18s | 两层路线图 | 「这条片子分两层」 |

三种可复用的开场型：**数量墙**（规模感）、**变换镜头**（效果类产品）、**对比定格**（两种范式）。
判断标准很简单：把第一帧截出来，别人能不能一句话说出“这片子讲什么”。

**反例：** 同一批素材里「不是文件，是配置」那张图很漂亮，但第一版把它放在第 10 秒——
开头那张大字卡换掉之后，这张图正好接上，变成了第三拍的“对比定格”。

## 30. 竖屏素材塞进 16:9 卡片：高度丢了 58%

**现象：** 用户说「有部分截取的视频感觉高度丢了一部分，导致显示不全」。

**实测：** 一条 600×800 的手机端录屏，为了塞进 1080×608 的卡片，裁成 `600:337`——
**只剩 42% 的高度**。裁掉的是页面顶部的导航和底部的说明文字，
观众看到的是一块“被截了一半的截图”。同一个问题出现在从 16:9 里裁竖构图资产卡时：
按肉眼估的 `400:640 @ y=70` 把卡片上的文件名切掉了一半，`y=70..710` 才完整。

**修法：**

1. 新增 `phone` 版式：片段帧按原比例贴着卡片边进设备卡（圆角 26px + 2px 描边 + 投影 + 顶部强调条），
   **不缩放、不裁切**；片段帧的分辨率直接由 `make_clips.py` 的 `CLIP_SIZE` 决定（如 585×780）。
2. 从 16:9 裁竖构图时，**按文字行量坐标**：抽一帧，用 PIL 统计卡片区域每行暗像素占比，
   连续区间就是一行字（实测某资产卡：590–615 分类 / 654–672 标题 / 679–698 文件名 / 715–737 说明），
   裁到行与行之间；别按肉眼估。
3. `phone` / `full` / `diptych` 这三种版式的卡片从 y≈470 起，**200px 大字会把卡片压住**
   （实测大字下缘 542，正好差 30px），所以 `render.py` 把这类版式的大字缩到 150px、基准线 240/262。

## 31. 两层次结构：只讲“它很厉害”，观众记不住

**现象：** 第一版是一条技术线（能力 → 原理 → 参数 → 结论），用户反馈
「文章应该有两个层次好玩：以前高不可攀的 3D 资产，现在轻松搞定，而且大量免费……
第二个层次，这个人在 AI 时代的做事方案：用 AI 生成素材、评估素材，然后免费 + 收费的模式」。

**原因：** 产品类文章的价值有两半：**用户能玩到什么程度**（画面证据）和**他怎么做到的**（机制 + 生意）。
只讲前者是广告，只讲后者是技术文档；两半都要，但要分层讲。

**改法：**

- 第一层（好玩 / 门槛）：每个小节配一个**能看见的镜头**——变装、换色、改比例、免费下载。
  答不上“这一节能给我看什么”的小节就是形容词，砍掉。
- 第二层（他的做法）：**生成 → 评估 → 定价**，每环都有数字或流程图。
  实测这一版把「Pro 15 美元/月解锁 HD 和 PBR」漏了，观众看完不知道它怎么赚钱——
  而这恰恰是“AI 时代做事方案”最值钱的部分。
- 两层之间用一句过渡（“第二层。这些资产不是请美术做的，是 AI 工厂造出来的”），
  `layers` 版式（上=第一层，下=第二层的三块）就是现成的路线图。

## 32. 换种子重挑一段，还不够

**现象：** 4 段 f0 = 254.3 / 238.6 / 258.7 / 242.8Hz，极差 20.1Hz，`check_voice` FAIL。
把 258.7 那段换种子重挑到 235.9Hz 之后，极差变成 **18.4Hz**——卡在 18Hz 门槛上，还是 FAIL。

**修法：** 谁偏离谁重挑，但要一直挑到**极差过线**为止，不是只修最差的那一段。
这一版第二次把 254.3 那段重挑到 240.0Hz，四段变成 240.0 / 238.6 / 235.9 / 242.8，极差 **6.9Hz**。
代价是每段 4 个种子约 16 分钟（40 秒音频 × 4 次），值得——音色漂移是“一耳朵”的问题。

## 33. `fix_boundaries` 也会把切点挪反方向

**现象：** 中文数字句（“两千六百多个”）的切点被 `fix_boundaries.py` 从 12.72s 挪到 13.55s，
这一句的镜头只剩 1.99 秒（23 个字），画面在句子中间就切了。

**原因：** 数字被 ASR 转成阿拉伯数字后，`difflib` 只匹配到“多个资产”，
切点落在“两千六百多”之后；静音判据发现切点“落在语音里”，就往后找最近的静音结束——
那正好是句中的一个微小停顿，于是越挪越晚。

**修法：** 不要盲信自动修复。流程改成：

1. `align_asr.py` 出词级时间戳；
2. 把 4 个长段的 ASR **段落**（`transcribe` 的 segment）打出来，人工把每个 beat 对到“句子起点”；
3. 写进 `asr_times.json`；
4. `build_audio_cont.py` 只做 `snap_to_onsets(tol=0.30)` 轻吸附（±0.3s 内贴到真实开口），
   不再做整段前移。

这一版 35 个 beat 的边界全部人工核过，`check_audio.py` 的章节切点偏差 ≤0.08s。

## 34. 「文字 + 视频」第一版做成竖裁整屏，主体全废

**现象：** 用户反馈「视频的比重还太少，纯文字的影响体验，可以视频+文字一起出现」。第一版把
`text` / `quote` / `data` 的文字卡改成「9:16 竖裁整屏视频 + 压暗 + 大字」，抽帧一看：
鸽子被裁成一面白墙、猫只剩一截黑影——观众根本看不出画面里在发生什么。

**实测：** 源片 3056×2160（**1.414:1**），竖裁 9:16 只取 **1215/3056 = 40%** 宽。
这批素材的机位是「动物在画面中偏右、周围全是白墙」，中心竖裁正好切掉主体、留下墙面。

**修法：** 按片段画幅分两档（`render.py` 的 `clip_is_wide()`）：

- **宽素材** → **满幅窗口**：文字在上（y≈170–420），原片按原始画幅 1080×764 放 y=470–1234，
  不裁不拉伸。`CLIP_CROP="3056:2150:0:5"`、`CLIP_SIZE=(1080,764)`。
- **竖素材 / 要复用的素材** → **模糊整屏底**：9:16 + `GaussianBlur(26)` + 亮度 0.62 + 上下渐变压暗。
  `CLIP_CROP="1215:2160:920:0"`、`CLIP_SIZE=(720,1280)`。

**顺带解决的第二个问题：** 同一段素材复用。猫那段只有 7.2 秒，被 01_00 / 01_02 / 01_05 / 01_06
四个镜头用；糊成 26px 之后看不出是同一段。**素材不够时，优先复用“会被糊掉”的那一档**，
别急着降速到 0.5×。

**结果：** 40 个镜头里 34 个有运动原片（原 17 个），纯色底只剩 2 个 `flow` + 1 个 `list` + 1 个 `compare`
（图表，当节奏停顿）。

## 35. 大字下划线压进画面：不是个别镜头，是版式参数

**现象：** 用户截图指出「七十年后」那一镜里，大字的下划线压进了视频画面，并说「同样的有几个地方」。

**实测：** `card` 版式大字基线写死 292、字号按宽度收到 200px。但 200px 的中文字形
`textbbox` 下缘在 **543**、下划线再 +16 = **559**，而卡片从 **540** 起 → **压进画面 19px**。
所有「`card` + 4–5 个字 + 200px」的镜头都中招（`先懵一秒` / `学会躺平` / `安全感没了`…）。

**修法：** 把「大字几何」抽成一处判据（`layout_text_box()` + `fit_text_in_box()`）：

```
下划线底 = textbbox()[3] + 16
卡片顶   = card/hook 540 · full/phone/diptych 470 · 结构版式 536 · text+窗口 470
要求     下划线底 ≤ 卡片顶 − 28
```

基线也一起往上收：`card` 292→268、`full` 262→236、`phone/diptych` 240→232。
「七十年后」现在 180px，下划线底 510、卡片 540，**留 30px**。

**关键教训：** 抽帧目检看不出这类问题（白墙背景尤其看不出），必须**按数字判**。
`check_text_gap.py` 就是把这个判据做成门禁：逐 beat 复算 bbox，间距 <12px 直接 FAIL。
改完扫描全片 40 个 beat，间距一律 29–30px。

**为什么不能只按宽度收：** `fit_big()` 只保证 `字体宽度 ≤ 960px`。中文的「宽」和「高」是
两个独立约束：4 个字 200px 只有 800px 宽（过），但高度照样 251px（不过）。

## 36. 同音字把切点带偏：拼音匹配

**现象：** 一条片子里 00_04 只有 1.63 秒（13 个字），算出来 8 字/秒——物理上不可能。

**原因：** Whisper 把「每俯冲一次」写成「没辅充一次」，`difflib` 的字符匹配找不到「每/俯/冲」，
把这个 beat 的第一个匹配字落到后面的「一次」上，边界晚了 0.8 秒。

**修法：** `align_asr2.py`——原文和转写都转成**不带声调的拼音**（`pypinyin`）再匹配；
数字先转中文读法（`0.3` → `零点三`，否则 `0`/`3` 永远匹配不上）。
切点回到 12.28 秒，`snap_to_onsets` 再吸到真实开口 12.62。
各 beat 的字/秒从「3.3–8.0」收敛到「4.6–6.6」。

**注意：** 拼音匹配解决的是「同音字」，不解决「ASR 把整句听成另一句」；后者仍要靠
`snap_forward_to_pause` 和人工核 2–3 个边界。
