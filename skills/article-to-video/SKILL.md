# 文章 → 解说视频

这是一套从真实公众号改稿中沉淀出来的生产流程：第一版 3:58 横屏被否，原因是“开头太静止、声音太快”；第二版 3:20 竖屏修正了节奏，但下划线压字、音色忽好忽坏；最终 3:00 版修掉了切换冻结、话没说完就切、尾音丢失。后来又补了一轮：文章没有配图、只有一条英文原片时，
从原片剪 6 段静音 B-roll（而不是全用截图），顺带修了白底图发灰、数据卡数字停在 0.3、标题数字贴边。
后来又补了一轮：一条人物片主题句写了、三件事也列了，观众还是说“三个方面太离散、听着发懵”。
问题不在配音和画面，在于把“他写了什么 / 他为什么躲 / 谁在替他挨打”三个并列的人物侧写
当成了论证。重做时只留一个突破点（“基座的账单”），其余素材全部降级成证据或一个镜头。
最新一轮（v4）补的是两件最容易返工的事：**开头 3 秒必须是画面 + 结论**（纯文字卡一律打回），
**竖屏素材不许塞进 16:9 卡片**（裁掉 58% 高度，观众说“显示不全”）；顺带给视频素材加了
`phone`（竖屏整帧）和 `diptych`（前后对照）两个版式，以及“第一层好玩 / 第二层怎么做生意”的两层次结构。
最新一轮（v7）是“**只给一个文章地址**”的完整跑通：Windows 路径 `E:\obsidian\...` 里带中文和全角引号、
8 张图全在 `assets/<文章标题>/file-*.png`、**没有任何原片**。这一轮补上 `article_prep.py`（文章地址 →
图片落地 + 配图体检 + 字数/时长预估 + 摘要），补上“只有插画、没有原片”的整条做法（结构版式垫模糊图，
纯色底从 20 个降到 2 个），还修了三个会静默毁掉片子的坑：**`VIDEO_*` 环境变量没进 `WSLENV` 就全部
静默回落到示例文案**、**`align_asr2.py` 的“首字匹配”把 4 个 beat 压成 0.45 秒**、
**英文开头的句子切点后跳 1 秒**。

下面的规则都是踩过坑之后留下的，按顺序执行。

**语言约定：同等条件下优先中文。** 文档、说明、字幕、口播都用中文；代码、命令、字段名保持原文。

## 适用场景

- “把这篇公众号文章做成视频” / article-to-video / Markdown → 带解说的 MP4。
- **用户直接给一个文章地址**（`E:\obsidian\推文\SRE\xxx.md`、`/mnt/e/...`、带引号/中文/全角引号）：
  先跑 `article_prep.py`（阶段 0 第 1 步），它把路径、图片、字数一次理顺。
- **给的是公众号链接而不是本地文件**：先用 `wechat-obsidian-archive` 存档成 Obsidian 里的 Markdown，
  再回到这里；不要拿网页 HTML 直接当文章读。
- Markdown 里的图片指向不存在的 `assets/...`，但图片就在文章同目录。
- 要做手机端竖屏（视频号 / 抖音 / 朋友圈）或 16:9 横屏。
- 已有视频出现：开头静止、语速太快/不可信、图片切换卡顿、字幕抢在话没说完前切换、尾音缺失。
- **用户说“开头不吸引人 / 直接划走了”**：先换第一帧（不是先改配音），见「开场铁律」。
- **用户说“截取的视频高度丢了一部分 / 显示不全”**：竖屏素材被塞进了 16:9 卡片，换 `phone` 整帧。
- **人物 + 产品类文章要“两个层次”**：先讲能好玩到什么程度（要有变装/换色这类画面证据），再讲他怎么用 AI 造、怎么收费。
- 用户说“开头相当部分不知道要讲啥 / 主题不突出 / 有点乱 / 几个方面太离散”：先别改配音和画面，先重找突破点、重写三问链（见阶段 1 的“先找突破点，再写主题句”）。
- 想用某条视频里的解说音色（“用这个声音重做”）：见阶段 2 的默认音色与 `make_voice_ref.py`。
- 文章只有文字，但有一套参考视频（英文原片 / 发布会录像）：从原片剪 **静音 B-roll**，不要只用截图。
- 想给一部分镜头加真实运动（蝴蝶扇翅、贴标签、走路），其余仍是静帧。
- **用户说“视频比重太少 / 纯文字影响体验 / 可以视频+文字一起出现”**：把文字/引语/数据卡垫到原片上面
  （满幅窗口或模糊动态底），纯色文字卡压到 ≤20%，见「视频 + 文字」一节。
- **用户截图指出“字盖住视频了 / 下划线压在画面上”**：别手改单个镜头，改 `layout_text_box()` 的判据，
  再跑 `check_text_gap.py` 量全片（规则 32）。
- 需要一套可复用的流程：字幕、解说稿、质量门。

## 硬性规则

1. **绝不把长段 TTS 按句切成小段。** 按估算停顿切，就是丢字的根源。长段音频整体保留，ASR 只用来定画面/字幕时间。
2. **切点对齐到“下一句开口”，不是停顿中点。** 上一句完整播完、下一句开始，才允许切画面。
3. **文字镜头之间不要叠化。** 两行大字或两张复杂插画叠在一起，看起来像渲染故障。硬切 + 连续运动更顺。
4. **每一帧都要动。** 停顿期间也保持线性推拉；文字卡加缓慢推近 + 光扫。先静止再突然跳，观众会感知为卡顿。
5. **下划线用字形 bbox，不能用字号估算，且留够 12–16px 空隙。** 中文字形下缘会超出 em 框，`y + font_size` 会正好压到笔画；实测 32px 小标签的墨迹下缘是 `y+42`，写死 `top+42` 就是 0 间距，线上沿贴着“年”的底边。小标签（eyebrow）的下划线尤其容易踩：字号小、线又短，差 4px 就显脏。统一用 `textbbox()[3] + 13`。
6. **验收解码后的 MP4，不是源帧。** 编码器会跳过低运动块；解码后连续多帧完全一样，才是真的冻结。
7. **保留旧版本。** 新版本放新目录或 `out/vN/`；不要覆盖用户要对比的版本。
8. **按手机屏幕验收。** 文字要在 1080×1920 上、避开右侧和底部平台 UI 后仍然可读。
9. **切点吸附到“开口”。** whisper 的词起点有 ±0.3s 误差，长段之间还有空白；必须把画面切点吸附到真实的语音起点，否则观众感知为“卡一下”。（`build_audio_cont.py` 的 `snap_to_onsets`）
10. **每个镜头单独运动。** 按场景计时推近，摊到 20–30 秒上每帧只动 0.0001，等于静止画面；要按 beat 计时、切镜头时重置。
11. **配图逐句判断，不要“每场景一张默认图”。** 一句讲规模、一句讲预算，却共用一张天平，观众立刻觉得“图不对文”。
12. **第一条音轨的 1 秒内不放音效。** 音乐还在淡入时叠 impact/whoosh，就是开头一声“刺啦”。
13. **一条主线讲透，胜过五条线各说一句。** 用户说“信息量太大/太跳跃”时，砍到一条线（2:00–2:30），而不是加速。
14. **有参考视频就优先用动态 B-roll。** 截图 + Ken Burns 只解决“在动”，解决不了“真的在发生”。4–8 个镜头换成原片片段，只借画面、不借原声（英文人声会和中文旁白打架）。
15. **片段不跨剪辑点、不循环、不在结尾冻结。** 按 beat 时长线性映射：素材短就自然放慢；循环会跳帧，停在末帧会被编码器判成静帧。
16. **片段镜头不再套整帧推近。** 推近会裁掉画面边缘（水印、手部），运动交给素材本身。
17. **白底/高亮图要按亮度自适应压暗底图。** 固定 alpha 150 会把白背景照片糊成一片灰，标题和字幕都没对比。
18. **参考视频选段看精确时间码 + 剪辑点，不要按缩略图序号猜。** 1fps 缩略图的序号和真实秒数会差半拍，很容易把“指尖捏着标签”剪成“研究员对镜头说话”。
19. **先定突破点，再写分镜；开头 15–20 秒内给结论 + 路线图。** 观众看完要记住的那句判断必须先写下来（例：“这 100 亿不是利润，是一张正在滚动的账单”／“他写了半个互联网，但养它的人不是他”），再决定讲什么。前 15–20 秒：钩子事实 → 突破点 → “只看三件事” → 第一件事；不要先讲 30 秒背景。每个章节都要回答**突破点逼出来的下一个问题**，章节标题连起来就是叙事线；删掉后突破点仍成立的章节，就是支线，砍掉或压成一个镜头。
20. **配图有空白边时，先量墨迹 bbox，再按比例选裁切方式——不是见白就裁，也不是照搬“同图放大模糊填空”。** 实测一张 1024×572 的插画，内容只占中间 **38.5% 宽**（左右各 31% 纯米色），塞进 1080×608 宽卡片就是“一张纸上画了个小人”，小人只有 416px。规则见阶段 0 第 3 步：`image_margins.py` 量内容占比 → 横竖都 ≥80% 不裁（留白是构图的一部分）；某边 <80% 就裁到内容，裁完宽高比 <1.15 用 `poster` 竖卡，否则仍用 `card`；图本身宽高比 ≥2.2（横幅）不裁，交给 `card` 的深色卡底分支。裁出来的衍生图放项目 `assets/`，不覆盖素材原图。
21. **版式要轮换，别让 40 个镜头长成一张 PPT。** 只有 `card`/`text`/`data`/`hook` 四种版式时，观众 30 秒就摸清了规律，后面讲什么都在“等下一张图”。有流程就用 `flow`、有对比用 `compare`/`bars`、有对话用 `chat`、有提交/日志用 `terminal`、有分层用 `layers`、有几个数字用 `kpi`、有几条特征用 `list`、有原话用 `quote`。硬指标：**同版式不连续出现、`text` ≤20%、每条片子 ≥8 种版式、每 15–20 秒换一次类型**。信息量没变，观感完全不同（实测 40 个 beat 用 13 种版式，35 个 beat 的片子用 14 种）。
22. **结构版式的字是“画面字”，不是口播。** `extras` 里每条 ≤18 字，超了渲染器截成 `…`；`big` 压到 3–6 字（下面已经有面板）。想让观众读的，交给字幕和口播。
23. **音色以“跟上一版像不像”为准，不以 `check_voice.py` PASS 为准。** 门禁是参考音 ±8%、段间极差 ≤18Hz、MFCC ≥0.985；系列视频必须跑 `check_voice.py --baseline 上一版/audio`：MFCC ≥0.99 是硬门槛，Δf0 ≤15Hz 只作参考（不同文稿语调本来差 10–20Hz）。旧门禁（±18%、≤30Hz）放过过一条 262Hz（参考 239Hz）的片子——数字上“在音区里”，听感就是“开头换了个人”。
24. **一条片子只做一次 atempo，且每段减速不超过 20%。** 先 0.78、再补 0.91（合起来 0.71）会叠加两次 WSOLA，声音发闷、像换了个人。要拉齐语速用 `TEMPO_MAP` 逐段从 `*_raw.wav` 一次到位；超过 20% 就重生成更慢的段，不要继续慢放。
25. **中文数字会被 ASR 转成阿拉伯数字，切点会落进句中。** “六千零七”→`6007`、“五千五百八十九”→`5589`，`difflib` 跳过这几段，切点被对到后面的英文词上（实测晚 1.3 秒）。跑 `fix_boundaries.py` 用静音判据修；**不要按字数估**——`14 万行 Fortran`、`±10⁻¹⁰ K` 这种英数混排会估歪。
26. **文章做视频，只买一个“突破点”，不做内容覆盖。** 突破点 = 一句反常识的判断 + 观众听完会改变的
    一个认知或动作，必须能写成“A，所以 B”。三个并列的人物侧写（他写了什么 / 他为什么躲 / 谁替他挨打）
    不是论证，是轶事集：观众听完“有点意思”，却说不出记住了什么。素材按“它证明了突破点的哪一半”取舍，
    答不上来的一律砍掉或压成一个镜头。见阶段 1「先找突破点」。
27. **开场 3 秒内必须有“画面 + 一句结论”。** 纯文字卡、标题卡、先讲背景都算失败；观众划走只发生在前 3 秒。
    三种可复用的开场（数量墙 / 变换镜头 / 对比定格）和四拍节奏见下面的「开场铁律」。
28. **竖屏、竖构图的素材不许塞进 16:9 卡片。** 实测 600×800 的手机录屏裁成 600×337 只剩 42% 高度，
    观众第一反应是“你没截全”。用 `phone` 版式整帧进设备卡；16:9 片段也不要为了“铺满”去裁上下。
29. **`phone` / `full` / `diptych` 的大字要缩一号。** 这三种版式的卡片从 y≈470 起，200px 的大字
    下缘在 542，正好压在卡片顶边（实测差 30px）。`render.py` 已经把这几种版式的 `big` 自动缩到 150px、
    基准线 240/262；自己写新卡片版式时也要先算这条。
30. **一条片子里，“只有字”的镜头不许超过 20%。** 观众的反馈是“纯文字影响体验、像 PPT 配音”。
    文字/引语/数据卡一律先把原片垫在下面（见「视频 + 文字」一节），纯色底只留给真正的图表
    （`flow` / `list` / `compare` / `bars`），并且**留 3–4 个当节奏停顿**，全塞满反而累。
    实测同一篇稿子：纯色文字卡 14 个（35%）被否；改成垫画面后 40 个镜头里 34 个有运动原片，
    纯色底只剩 4 个图表，观感从“PPT”变“纪录片”。
31. **“视频 + 文字”按片段画幅分两档，不许把 1.4:1 的素材竖裁 9:16 当整屏底。**
    宽的（≈1.41:1）→ **满幅窗口**：文字在上（y≈170–420），原片按原始画幅铺 1080×764 放在 y=470–1234，
    不裁不拉伸；竖的/要复用的 → **模糊整屏底**：9:16 铺满 + 高斯模糊 26px + 压暗 0.62。
    实测把 3056×2160 竖裁成 1215×2160 只剩 40% 宽：鸽子被裁成一面白墙、猫只剩一截黑影，
    观众根本看不出画面里发生了什么——这是第一版返工的直接原因。
32. **大字必须按字形 bbox 收字号，不能只按宽度收。** 判据：`textbbox()[3] + 16 ≤ 卡片顶边 − 28`。
    200px 中文字形下缘在 base+251，`card` 卡片从 540 起 → 下划线压进画面 19px（用户截图指出，
    “七十年后”那一镜）。`render.py` 的 `layout_text_box()` + `fit_text_in_box()` 是唯一算式，
    `check_text_gap.py` 用同一套量全片；改完必跑，实测合格是 29–30px 间距。
33. **Windows python 从 WSL 启动只继承 `WSLENV` 里列出的变量。** `VIDEO_BRAND` / `VIDEO_END_*` 没登记，
    `render.py` 会**静默**用默认值：品牌名变成示例文案、结尾卡写“有些事，人类早忘了”。成片能出，
    错在最显眼的两处。`run_env.sh` 里必须把这些变量塞进 `WSLENV`，并在渲染前抽一帧确认。
34. **整片只有文章插画、没有任何原片时，结构版式不许留纯色渐变底。** 十几张图表全是纯色底，
    观众的评语就是“像 PPT 配音”。`render.py` 的规则是：有片段用片段（`clip_bg_fill`），
    没片段就用这一镜的 `img` 做模糊底再压暗 0.38。实测 47 个 beat 的纯色底从 20 个降到 2 个
    （只剩 `data` 卡），观感从“PPT”变“纪录片”。
35. **配图自带的中文标题，不要和画面大字重复。** 这批插画是“图 + 中文标注”一体生成的：
    `alarm.png` 上写着“AI 先到场”，第一镜大字就不能再写“AI 先到场”——观众会以为字幕卡了两遍。
    改成**图上的字没说**的那半句（“第一个不是人”“只干一件事”“贵到跑不起”），图和字才是互补。
    决定 `big` 之前，先把图放大看一眼它自己写了什么。
36. **结尾卡的两行字也按 `textlength` 收字号。** 100px × 9 个中文 = 1000px，1080 宽只剩 40px 边距，
    手机上会被平台 UI 压住（安全区要求左右 ≥60px）。`endcard()` 现在自动缩到 ≤960px；
    但你写 `VIDEO_END_2` 时仍要自己读一遍：超过 8 个中文字，先想想能不能更短。



## 开场铁律：前 3 秒决定有没有人看（v4 新增）

**所有视频都适用。** 实测一条 3 分钟的片子，被否的第一句反馈永远是“开头不吸引人，直接划走”——
它跟内容质量无关，是**前 3 秒没给画面、没给结论**。返工时先换画面，不要先改配音、先调语速。

### 0–3 秒：画面 + 一句结论

- **必须有动的东西**：动态片段、计数动画、变换中的模型。静态大字卡最多 1 秒，且后面立刻接画面。
- **必须有一句反常识的结论**，不是背景介绍。例：「两千六百多个 3D 模型，全部免费，而且每一个都能改。」
- **不要**：标题卡、LOGO、「大家好，今天聊聊……」、「随着 AI 的发展……」。

### 三种可复用的开场（按素材选）

| 型 | 用什么画面 | 实测例子 | 适合 |
|---|---|---|---|
| **数量墙** | 素材里“一大片同类东西”的镜头铺满卡片，配计数动画 | 2,660 个低模铺满屏幕，官方计数器从 1,223 滚到 2,600+ | 有规模感的产品/数据集 |
| **变换镜头** | 第一秒就是“它在变”（换装、变形、长出来），竖屏素材用 `phone` 整帧 | 警长从警服换成海盗大衣，全程 3.8 秒 | 效果类产品、对比类内容 |
| **对比定格** | 一张“前后对比”的图/表，左右两边一眼看出差别 | 左边冻结的网格、右边可调的程序 | 反常识是“两种范式”时 |

### 前 16–20 秒的四拍

1. **0–4s 最炸的画面 + 结论**（数量墙）
2. **4–9s 第二炸**（变换镜头 / 真实录屏）
3. **9–13s 一句判断**（把反常识说死：以前高不可攀的 X，现在是 Y）
4. **13–18s 路线图**（`layers` / `flow`：这条片子分两层 / 三件事）+ 立刻进第一件事

四拍之外不要塞任何铺垫。实测 v1 用“冻结的网格”一张静态大字卡开场，被一句话否掉；
v2 换成「数量墙 → 换装 → 拖滑块 → 两层路线图」，同样的文稿，完播率结构完全不同。

### 返工顺序（用户说“开头不吸引人”时）

1. 先问：**第一帧是什么？** 如果是文字卡，先换成素材里最炸的一个画面。
2. 再看第一句：**它是不是结论？** 不是就改成“数字 + 判断”。
3. 最后才动结构：把最炸的两段提到 0–9 秒，背景全部后移或砍掉。

## 视频 + 文字：让画面占住镜头（v5/v6 新增）

**适用场景：** 用户说「视频比重太少 / 纯文字影响体验 / 可以做视频+文字一起出现」，
或者你自己看片时觉得中段像 PPT 轮播。第一反应不是“加动画”，是**把画面垫到字下面**。

### 先算清楚：哪些镜头没画面

```bash
# 数一遍：哪些镜头还没有画面
python -c "import script_data as d; bs=d.flatten(); print(len(bs), [b['id'] for b in bs if not b['clip']])"
```

一条 40 镜的片子，第一版通常有 14 个纯文字/数据卡。目标是压到 **8 个以内**（只剩图表）。

### 两种处理，按片段画幅选（这是关键）

| 底下是什么 | 用于 | 几何 | 为什么 |
| --- | --- | --- | --- |
| **满幅窗口** | `text` / `quote` / `data` | 大字在上（y≈170–420）＋原片按**原始画幅** 1080×764 放 y=470–1234 | 不裁不拉伸，画面完整；字和画面各占一块 |
| **模糊整屏底** | `list` / `compare` / `chat` / `bars`，以及**要复用同一段素材**的文字卡 | 9:16 cover + `GaussianBlur(26)` + 亮度 0.62 + 上下渐变压暗 | 面板要占住 536–1180，清晰画面会和图表抢；糊掉后只留运动感，**顺带把“同一段素材用四次”变成看不出来** |
| 原样 | `card` / `full` / `phone` | —— | 本来就是“画面 + 大字” |

判断依据是**片段帧的宽高**，不是版式名：`render.py` 的 `clip_is_wide()` 读 `f_0001.jpg` 的头，
宽帧（1080×764）走窗口，竖帧（720×1280）走模糊底。这样 `quote` 既能进窗口（03_05），
也能当模糊底（02_05），不用给版式写死。

### 素材怎么分配（108 秒原片撑 40 个镜头）

1. **先列已用区间**，按镜头号排开（`video_sheet.py` 的剪辑点表就是边界），剩下没用的才是候选。
2. **按语义配**：讲“鸽子最慌”就垫鸽子那 2.3 秒（22.8–25.15），讲“水就是重力”就垫鱼缸（82.6–89.6）。
   不要因为“这段没用过”就随便插一段别的动物。
3. **不够时按“糊掉复用”排序**：先复用被模糊后看不出内容的（猫那 7 秒被 4 个镜头用），
   再考虑降速（0.8–0.9× 是自然慢放，0.5× 以下只适合“刻画动作”的镜头）。
4. 每个片段的 `CLIP_SIZE` / `CLIP_CROP` 跟着处理方式走：
   - 窗口：`CLIP_CROP = "3056:2150:0:5"`（和 `full` 卡同一套裁切，几乎不裁）、`CLIP_SIZE = (1080, 764)`
   - 模糊底：`CLIP_CROP = "1215:2160:920:0"`（9:16 中心裁）、`CLIP_SIZE = (720, 1280)`（反正要糊）

### 字怎么摆（不是简单往上挪）

- `data`：数字从 y=260 提到 **140**，**说明行挪到窗口下面 y≈1250**，`DATA_SOURCE` 这一行在窗口版式里省掉。
- `text`：去掉装饰引号、eyebrow 从 600 提到 **118**（原来会和大字一起挤在窗口上沿），
  big 基线 172；有窗口时 `cap_for` 的字幕仍在 1400+，不打架。
- `quote`：字号 72 → **54**、只排 3 行，整块贴在窗口上方（y=150 起）。
- **描边**：数据主数字、说明行、引语都加 3–4px 黑色描边。这批素材是白墙背景，细字压上去会糊。
- 窗口版式**不再套整帧推近**（画面自己在动），但仍保留光扫。

### 验收（两个数字）

1. `python check_text_gap.py` —— 36 个带大字的镜头，间距一律 ≥12px（实测 29–30px）。
2. 抽 4 帧看：窗口版式下大字离画面 ≥25px；模糊底版式下图表能看清；字幕没被窗口压住。

**踩过的坑（按代价排序）：**

| 做法 | 结果 |
| --- | --- |
| 9:16 竖裁做整屏底 | 主体只剩 40% 宽，鸽子=白墙、猫=黑影，整段作废 |
| 只把文字变半透明压在整屏视频上 | 白墙背景上大字仍糊，必须「窗口分层」或「模糊+压暗」 |
| 大字按 200px 写死 | `card` 版式下划线压进画面 19px（见规则 32） |
| 只给 3–4 个镜头垫画面 | 观众感知不到变化，要么全改要么不改 |

## 只有文章配图，没有原片（v7 新增）

公众号文章常见形态：正文 + 8 张「图 + 中文标注」的一体图，**没有一条视频**。
这种片子观众最容易说“像 PPT”，而改法不是加动画，是**让图表版式也垫上画面**。

### 判据：先数一遍“没画面的镜头”

```bash
python -c "import script_data as d; bs=d.flatten(); print(len(bs),
      [b['id'] for b in bs if b['layout']=='data' or not b['img']])"
```

- 配图要给**每一镜**（`flatten()` 里 `img=None` 就回落到场景 `default_img`），不许出现 `img=None` 的 beat；
- `card` / `hook` / `full` 显示清晰插画（一镜一图，观众真正在看内容）；
- `text` / `quote` / `data` 用同一张图**模糊 + 压暗**当底（大字在上）；
- `chat` / `layers` / `flow` / `compare` / `bars` / `kpi` / `list` / `terminal` 在**没有片段**时，
  自动退到这一镜的 `img` 模糊底（`render.py` v7 起的默认行为），压暗 0.38 之后面板不抢字。

实测（47 beat / 8 张图 / 3:11）：20 个清晰插画卡 + 7 个 `text` 模糊底 + 18 个图表模糊底 +
**2 个纯色**（只剩 `data` 卡）＝ 纯色 4%，`qa` 的“像不像 PPT”这一关直接过了。

### 8 张图撑 47 个镜头：怎么分配

1. **一图一章**：图是随文章段落生成的，语义天然对齐。先按章节把图分组（例：账单章 → 账单图），
   章内所有 beat 都用这张图（清晰卡 2–3 个，其余模糊底）。
2. **清晰卡只给“这句话需要看细节”的镜头**（数字、对比、流程），其余一律模糊底——
   同一张图在一章里出现 5 次也不会腻，因为观众只在 2 次里看清它。
3. **图表版式按语义挑图**：讲成本就垫账单图、讲基准就垫评分板图；宁可重复，不要让“讲成本”垫一张团队合影。
4. **`data` 卡留给纯数字**（1/8、80/90），它是唯一该纯色底的版式，也是全片节奏的呼吸点。

### 代价与边界

- 没有真实动作：全片靠 13 种版式轮换 + 每镜推近 + 光扫维持“在动”，**仍然过不了“真实发生”这一关**；
  有原片时优先用原片（规则 14），这条只是没有原片时的最优解。
- 插画里的中文标注会和大字“打架”（规则 35）：先看图再定 `big`。
- 图片链接常在 `assets/<文章标题>/file-<时间戳>.png`，目录名带全角引号 → 别手抄，用 `article_prep.py`。

```bash

# 第一步永远是它：文章地址 → 图片落地 + 配图体检 + 字数/时长预估 + 素材摘要

# → out/article_digest.md + assets/img*.png + 可直接粘的 IMG = {...}
```

然后：

1. 读 `out/article_digest.md`：**先看“字数 → 时长预估”**，原文 2000 字就是 6 分钟，
   要 2:15–3:15 就得砍掉四到五成；砍不动就是还没找到突破点（阶段 1）。
2. 改 `script_data.py`（场景、beat、`img` 文件名用 `article_prep.py` 给的 `img01.png`；要动态片段时写 `VIDEO_SRC` / `CLIP_SRC` 并在 beat 第 9 位标 `True`）。
3. 选音色：默认用内置 `voices/q1`（女声，已去伴奏），直接就能配音；要换音色用 `make_voice_ref.py`，或把 4–8 秒的 `audio/prompt_ref.wav` 放进项目（项目内的会覆盖内置音色）。
4. 改 `project_config.py` 的 `EXCLUDE`；配音、对齐、构建三个脚本共用这一份，保持一致。
5. 如果图片不在项目目录，设置 `ASSET_DIR`，或渲染时传 `--assets <dir>`。
6. **写 `run_env.sh` 并 `source` 它**：`PY`、`FFMPEG`、`VOX_MODEL`，以及 `VIDEO_BRAND` / `VIDEO_END_*` /
   `VIDEO_SOURCE` 这些文案变量。最后**把 `VIDEO_*` 全部登记进 `WSLENV`**（见规则 33），
   否则 Windows python 看不到，成片会带着示例品牌名出厂。

`build_audio_cont.py` 和 `align_asr.py` 会自动推导 `GROUPS`：每 2 个场景一段，所以 8 个场景 → 4 段，3 个场景 → 2 段；场景数为奇数时，最后一段只含 1 个场景。

| 阶段 | 产出 | 通过标准 |

| 0 素材 | 图片映射、空白边测量与裁切、参考视频镜头区间、画幅决策 | 每张图/每段都看过并匹配段落；`image_margins.py` 报过一遍 |
| 1 脚本 | `script_data.py`，35–50 个 beat、≥8 种版式 | **0–3 秒有画面 + 结论**；前 20 秒四拍走完（炸点→炸点→判断→路线图）；三问能用“所以”串起来；总长 2:15–3:30；同版式不连续 |
| 2 配音 | 2–4 个长段 WAV | `check_voice.py` PASS：参考音 ±8%、段间极差 ≤18Hz、MFCC ≥0.985；`--baseline` 与上一版 MFCC ≥0.99 |
| 2.5 清理 | `clean_audio.py` 处理过的长段 | 段首无瞬态、长停顿 ≤0.55s、语速统一；每段只做一次 atempo（≥0.80） |
| 3 音频 | 连续 `narration.wav`、音乐/音效、混音 | `check_audio.py` PASS：开头无瞬态、无爆音、切点=开口、−16 LUFS |

| 5 渲染 | 1080×1920 或 1920×1080 MP4 | 每个镜头都在动，无叠化，配图逐句对得上；**纯色文字卡 ≤20%**，`check_text_gap.py` PASS（大字离画面 ≥12px） |
| 6 QA | 自动报告、截图、README | CFR、解码干净、无冻结窗口 |

## 阶段 0 — 素材与图片（含参考视频）

1. **先跑 `article_prep.py <文章地址>`**，再读 `out/article_digest.md`。一次拿到：
   标题/章节/段落、每个图片链接解析到的真实文件、字数与时长预估、出现过的数字清单。

   ```bash
   python article_prep.py "E:\obsidian\推文\SRE\某篇.md"       # 默认把图复制到 assets/img01.png
   python article_prep.py ../../06/某篇.md --no-copy              # 只体检，不动文件
   ```

   路径两种形态都认：bash 用 `/mnt/e/...`，Windows python 只用 `E:/...`（脚本内部互转，别自己手改）。
   图片链接里常见的坑它一并处理：`%20` 编码、`assets/<文章标题>/` 这种带全角引号的目录、
   Obsidian 的 `![[x.png]]` 写法、以及“链接指向的文件根本不存在”。
2. **逐张打开确认内容对得上段落，不能只看文件名。** `article_prep.py` 只保证“文件存在、尺寸和内容占比”，
   保证不了语义：一张“账单对比图”放在“团队介绍”那段就是错配。把摘要里的配图清单当核对表，
   一张一张看，同时记下**图上自带了哪句中文**（决定 `big` 不能写什么，规则 35）。
3. **量一遍空白边，别把“纸上的小人”塞进宽卡片。** 素材常是“一张大画布 + 中间一个插画”，
   直接进 1080×608 的卡片，两侧会剩几百像素。先跑：

   ```bash
   python image_margins.py ../06          # 逐张报内容占比 + 建议
   python image_margins.py ../06 --crop   # 按建议裁到项目 assets/
   ```

   脚本按四角中位色求背景、用“整列/整行墨迹占比”求 bbox（一个杂点撑不大 bbox），
   然后按这张表给建议——**重点是“看情况”，不是见白就裁**：

   | 情况（实测占比） | 判断 | 处理 |
   |---|---|---|
   | 图本身宽高比 ≥ 2.2（1536×383 这类横幅） | 超宽 | **不裁**，`card`；渲染器会自动走深色卡底（gap > 0.28h），别用“同图放大模糊填空” |
   | 内容横竖都 ≥ 80%（16:9 插画通常 84–100%） | 空白不多 | **不裁**，`card`；四周那点边是构图的一部分，裁完贴边反而难看 |
   | 某边 < 80%，裁完宽高比 ≥ 1.15 | 两侧/上下空白 | 裁到内容，仍用 `card`，图自然变大 |
   | 某边 < 80%，裁完宽高比 < 1.15（近方/竖） | 纸上的小人 | 裁到内容 **+ 换 `poster` 版式**（卡片按图比例收窄，图铺满卡片，留白交给深色背景） |

   裁出来的图放项目 `assets/`，`script_data.py` 里直接写文件名：`render.py` 先找 `--assets`
   目录，找不到再回落到项目 `assets/`，所以**不用覆盖用户素材，也不用把整份素材复制一遍**。
4. 检查尺寸/比例，排除重复图、无关截图。
5. 选画幅：
   - **9:16，1080×1920**：手机优先、视频号、抖音。用户说“普通手机用户”“划走”时默认竖屏。
   - **16:9，1920×1080**：只在文章内嵌播放器或用户明确要横屏时使用。
6. 每个版本单独建项目目录；图片可只读引用，不能覆盖旧版本。

**如果文章没有配图，但有一套参考视频：**

1. 先跑 `python video_sheet.py --video ../03/01.mp4`：输出逐秒缩略图（带精确时间码）、
   剪辑点、镜头区间。挑片段只在这个区间表里选。
2. 选 **4–8 段、每段 2–6 秒**、内容真的对得上台词的镜头（贴标签的手指、扇翅的蝴蝶、
   举网的人、被啃过的乳草叶子）。宁少勿滥；其余镜头继续用静帧或数据/文字卡。
3. 每段都**亲眼看帧确认内容**（`ffmpeg -ss <秒> -i 01.mp4 -frames:v 1 x.png`）。
   不要相信文件名，也不要相信缩略图序号。
4. 在 `script_data.py` 写 `VIDEO_SRC` 与 `CLIP_SRC = {"beat_id": (起点, 终点)}`，
   并在该 beat 元组第 9 位标 `True`。
5. `python make_clips.py` 切出 `clips/<beat_id>/`（1080×608、30fps、JPEG 帧序列 + `meta.json`）。
6. 预览 `python render.py preview <片段时刻>`，确认内容对、边缘没被推近裁掉。

片段只当画面：原片人声一律不用，音轨仍是中文旁白 + 垫乐。16:9 片段正好铺满 1080×608 卡片；
源片只有 854×480 也可以，lanczos + 轻度 unsharp（0.45）升采样，配上真实运动比静帧耐看。

**两条视频混着用（v4 新增）**：一条横屏演示 + 一条竖屏手机录屏很常见。`make_clips.py` 原来只吃一条
源片，现在有三个可选开关：

```python
CLIP_FILE = {"01_01": "../../19/手机端实录.mp4"}   # 个别片段换一条源片
CLIP_CROP = {"00_01": "400:640:680:70"}           # 先裁 w:h:x:y，再缩到卡片尺寸
CLIP_SIZE = {"00_01": (475, 760),                 # 覆盖卡片尺寸：竖构图配 phone 版式
             "01_01": (585, 780)}
```

- **竖屏素材整帧进 `phone`**，不要为了塞进 16:9 去裁上下（实测 600×800 裁 600×337 只剩 42% 高度，
  观众直接说“显示不全”）。
- **从 16:9 里裁竖构图时，按“文字行”量坐标，不要按肉眼估。** 卡片上通常有标题、文件名、说明三行；
  裁到说明行中间就是“半行字被切掉”，比不裁更难看。量法：抽一帧，用 PIL 找卡片区域里连续的暗行，

  ```python
  col = np.asarray(Image.open("frame.png").convert("L"))[:, 700:1200]
  dark = (col < 120).mean(axis=1)          # 每行暗像素占比
  runs = [(y) for y in range(540, 760) if dark[y] > 0.01]   # 连续区间 = 一行字
  ```

  实测某资产卡的文字行是 590–615（分类）/ 654–672（标题）/ 679–698（文件名）/ 715–737（说明），
  裁 `70..710` 正好一行不切；按肉眼估的 `70..640` 会把文件名切掉一半。
- **横竖混排时版式也要换**：横素材 `card`（1080×608），竖素材 `phone`（`CLIP_SIZE` 给竖尺寸），
  别用同一个卡片硬套。

## 阶段 1 — 脚本与分镜

目标总长 **2:15–3:30**（单点讲透 2:15–3:00 最常见），语速 **5.2–5.8 中文字/秒**，通常 850–1100 字。第一版 1667 字、7.8 字/秒，即使 3:58 也显得急。

**密度优先于覆盖。** 公众号原文常有 4–6 个并列论点；视频里一次只讲一条主线，宁可从 3:20 砍到 2:15。
判据：如果一条线只能用一两句带过（“行业也在跟进”“你也可以自测”），就不要放进视频——一句带过等于没说。
被否的两版分别是：45 个口号各说一句（太跳跃）、5 条线塞进 3:20（没说透）。

### 先找突破点，再写主题句（v3 新增）

“主题句”这个词会骗人：写一句关于文章的话很容易，写一句**替观众下的判断**很难。
实测一条人物片，主题句是「他写了半个互联网，却把名字藏了起来」——这是对事实的描述，
主角是“他”，观众既没有代价也没有收获；三个支撑问题（他写了什么 / 他为什么躲 / 谁在替他挨打）
彼此独立，每章都能单独成篇。观众的原话是「三个方面太离散，听着有点发懵」。

**突破点 = 一句反常识的判断 + 观众的代价。** 同一篇素材，重做时只留一句：
「他写了半个互联网，但养它的人不是他。」——反常识（大神＝名利双收，其实不是）、有代价
（有人拿命填）、观众带走的是“你用的免费基座，账单落在维护者身上”。素材没变，
主线从“他这个人真神”换成“这件事的账怎么算”，三章立刻变成一条因果链。

写之前先过四问，答不上来就别开写：

1. **反常识吗？** 观众的默认是什么，这句话推翻了哪一条。
2. **有代价吗？** 谁付了什么（时间/钱/健康/名声）。没有代价的“厉害”，观众只会“哦”。
3. **观众会因此改变什么？** 一个判断或一个动作（下次用免费工具时想起维护者／做开源前先想清楚谁守）。
   说不出来，就是知识搬运，不是突破点。
4. **25 字内能说完吗？** 说不完＝还没想清。

把这句话原样写进 `script_data.THESIS`：封面、标题、收尾的回调都用它，保证一以贯之。

然后才是三问链。**三问不是三个话题，是三个后果**：每一问都由上一问逼出来。

- 正例（Bellard 片重做版）：「基座有多大（所以账单很大）→ 他为什么先跑（所以账单转手）→ 落在谁头上
  （所以有人拿命去填）」。
- 反例（同一篇的初版）：「他写了什么 / 他为什么躲 / 谁在替他挨打」——三个并列话题，用“所以”串不起来。

三个测试：

- **连读测试**：把章节 `label` 用“所以 / 但是”串一遍，串不成句子就是并列素材。
- **换题测试**：把文章换成同主题的另一篇，这套结构还成立吗？成立说明在套模板，没找到这篇的突破点。
- **删章测试**：删掉某一章，突破点还成立吗？成立＝支线，砍掉或压成一个镜头。

素材取舍也用它：每条素材先回答“它证明了突破点的哪一半”，答不上来一律不进片。本片因此砍掉了
π 的对比数字、反社交的细节、Amarisoft 的来历，只留“他连破纪录都不开发布会”一个镜头证明“他造完就走”。

**时长**：单点讲透 2:15–3:00 就够。不要用支线凑到 3:30——凑出来的时长，观众用划走投票。

**开头 15–20 秒定式**：钩子（一个反常识的事实）→ 突破点（一句判断）→ 三问链（“只看三件事：…、…、…”）
→ 第一问。不要先讲 30 秒背景。四拍节奏与三种开场型见上文「开场铁律」。

### 两层次结构：先讲“能好玩到什么程度”，再讲“他怎么做的”（v4 新增）

人物 + 产品类文章最容易写成一条技术线：能力 → 原理 → 参数 → 结论。观众听到第三分钟仍然不知道
“这东西跟我有什么关系”。实测被否的原话是「两个方面太离散」「不知道要看什么」。

改成两个层次，每层 3–4 个小节，层与层之间用一句过渡（“第一层的答案在一个函数里”“第二层，这些资产
不是请美术做的”）：

| 层 | 回答的问题 | 每小节必须有的东西 | 实测小节 |
|---|---|---|---|
| **第一层：好玩 / 门槛** | 这东西让我能做到什么以前做不到的事？ | **画面证据**：变装、换色、改比例、免费下载——每个论点都要有一个能看见的镜头 | 一个函数（为什么能改）→ 拖一下（吊臂 / 换装 / 森林）→ 免费且通吃（2,660 免费、GLB+ES、骨架冻结）→ 连 agent 都能用 |
| **第二层：他的做法** | 他一个人怎么造出来、怎么卖出去？ | **机制**：生成 → 评估 → 定价，每一环要有数字或流程图 | AI 生成（一个 agent 写、175 个/周）→ AI 评估（judge 打分、2/3 退回、633 条意见变规则）→ 免费引流 + Pro 收费 → 成绩 |

判据：

- 第一层的每个小节，**问一句“这一节能给我看什么”**，答不上来就是形容词，砍掉。
- 第二层的每个小节，**问一句“机制是什么”**，只有结论（“AI 很高效”）就是口号。
- **商业模型不要漏**：免费层给什么、付费层卖什么、价格多少。实测上一版把“Pro 15 美元/月解锁 HD 和 PBR”
  整条漏掉了，观众看完不知道它怎么赚钱——而这正是“AI 时代做事方案”最值钱的部分。
- 两层之间要有过渡句，不要硬切；`layers` 版式（上=第一层，下=第二层的三块）是现成的路线图。

实测（100 亿项目）：v1 68 个 beat、4:53，开头 18 秒只给数字和“钱转一圈”，接着 36 秒讲三层关系，
中段又单独用 34 秒讲“卖铲子”，反馈是“开头相当部分不知道要讲啥、主题不突出”。v2 砍到 65 个 beat、4:52，
前 17 秒给结论 + 路线图，章节标题即叙事线，砍掉卖铲子整章、只留一句注脚；同样的时长，主线清楚了。
改的是结构，不是语速和画面。

用户明确要 5 分钟时，不要用支线凑时长：把同一个突破点拆成更多层证据（例：是什么钱 → 谁在付 →
什么时候停 → 最后转给谁），每一层都回答上一句留下的问题。

**段落式写法，不要口号式拆分。** 每个 beat 是一句完整的话，整段连起来要能读通：

1. 话题句 → 2. 证据（数字/例子）→ 3. 承接下一段的句子。
   例：「那这条边界，是怎么画出来的？」→「第一个条件，是技能半衰期足够短。」→「过去…能用四五年」→「但现在被压缩到一到三年」→「不是人变笨了，是工具贬值太快」。
   反例（口号式）：「被买断的六万人，不是因为能力差。」「真正值得琢磨的不是规模，是边界。」——两句都是结论，中间没有承接，连读像标题滚播。

结构：

1. **钩子（0–3 秒）**：一句具体、反常识的话。例如“一个 AI，为了查清公园门口谁人多，连轴转了十一天。” 开头必须有运动，不要 15 秒静止标题。允许 1 秒动态标题，然后立刻切。
2. **冷开场（3–20 秒）**：4–6 个镜头，每个 2–5 秒，交代前提和最离谱的细节。每出现一个新事实就切。
3. **主体**：4–6 个章节，一个镜头一个观点。保留原文数字和对方回应，不要把评论写成断言。
4. **反转**：反直觉的那句话（“最冷的一句话” / “天网没来”）。
5. **收尾**：短回调 + 一个开放问题，不要长总结。

单个 beat 的字段（`script_data.py`）：

```python
{
  "id": "00_01",
  "text": "它连轴转了十一天。",              # 口播；标点会影响停顿
  "sub": "它连轴转了十一天",                  # 字幕，每行 ≤ 15 个中文字
  "big": "11 天",                          # 画面大字，3–9 字
  "layout": "card",                        # 图片版式或结构版式，见下
  "accent": "orange",                      # orange | cyan
  "eyebrow": "连轴转",                     # 小标签
  "img": "file-....png",                   # 单 beat 覆盖图片
  "extras": {...},                         # 结构版式的数据（元组第 10 位）
}
```

规则：

- 一个 beat = 一句字幕 = 一次画面变化。短于 0.8 秒的碎片合并；超过约 28 个中文字拆开。
- 字幕最多 2 行，1080 宽、64px 时每行 ≤ 15 个中文字。长句要手动写 `\n`，不要依赖自动换行。
- `big` 用来说观点，不要重复字幕全文；如果图片里已经有同一句话，换一个角度。
- `text` 里不要放 Markdown、链接、括号备注、舞台提示。

### 版式别只会 `card` + `text`（v2 新增）

第一版的问题不是内容不对，是**每个镜头长得都差不多**：配图卡 + 大字卡 + 数据卡循环 60 次，
观众在 30 秒内就失去“下一屏会变”的预期。`render.py` 现在有 15 种版式，两条腿走路：

| 类别 | 版式 | 什么时候用 |
|---|---|---|
| 图片 | `card` / `full` / `poster` / `cover` | 有对得上的素材；竖幅实拍用 `cover`，竖构图插画用 `poster` |
| **视频** | `card`（16:9 片段）/ **`phone`**（竖屏整帧）/ **`diptych`**（前后对照） | 参考视频剪出来的 B-roll：横素材进 `card`，手机录屏/竖构图进 `phone`，换装/配色这类“前后”用 `diptych` |
| 文字 | `hook` / `text` / `quote` / `data` | 钩子、观点、官方原话、单个数字 |
| 结构 | `chat` / `layers` / `flow` / `compare` / `bars` / `kpi` / `list` / `terminal` | 讲“谁跟谁说话 / 分成几层 / 分几步 / 两边差别 / 谁快谁慢 / 几个数 / 几条特征 / 一次提交” |

`phone` 和 `diptych` 是 v4 专为**视频素材**加的两个版式：

- **`phone`**：片段帧按原比例贴着卡片边进“设备卡”（圆角 + 2px 描边 + 投影 + 顶部强调条），
  **不缩放、不裁切**。前提是 `make_clips.py` 里给这一段配 `CLIP_SIZE`（竖尺寸，例如 585×780 / 475×760）。
  实测 600×800 的手机录屏塞 16:9 卡片只剩 42% 高度，观众会说“显示不全”。
- **`diptych`**：左右两张**从片段里抽的帧** + 各自标签，讲“换装前 / 换装后”。抽帧用
  `ffmpeg -ss <t> -i src -frames:v 1 -vf crop=w:h:x:y -y assets/x.png`，两张图按同高摆放。
  它是“视频 + 静态对照”的混用：动态镜头先演一遍，diptych 再把前后钉住，观众才看得清差别。

结构版式不依赖素材，靠程序画，数据和文案写在 beat 元组第 10 位的 `extras` 里
（`script_data_template.py` 有全部字段示例）：

```python
# 群聊消息流：左人右 AI，气泡逐条出现，最后一条会先显示“正在输入”
("起因只是群里一句随口的抱怨。", "起因只是群里\n一句随口的抱怨",
 "一句抱怨", "chat", "orange", "工作群", None, "",
 {"title": "飞书 · 产品技术群", "badge": "9 人在线",
  "msgs": [
      {"who": "前端 小明", "role": "user", "tag": "没人 @ 它",
       "text": "窗口没聚焦时点会话会变成双击，我每天误触十几次。"},
      {"who": "Super-agent", "role": "agent", "tag": "自主动手",
       "text": "已复现，根因找到，修复写好了，PR 也提了。"},
  ]})

# 条形对比：数值条生长，适合“快了多少”
("结果是这样。", "结果是这样", "快了多少", "bars", "orange", "任务完成时间", None, "",
 {"rows": [{"label": "单会话 · p95", "value": 29.5, "text": "29.5 分钟"},
           {"label": "Super-agent · p95", "value": 15.7, "text": "15.7 分钟", "strong": True}],
  "max": 32, "note": "p95＝95% 的任务在这个时间内完成"})
```

轮换规则（按 40 个 beat 的实测）：

1. **同一版式不连续出现两次**（`hook` 收尾的 2 秒短切除外）；`text` 全片不超过 20%。
2. **每 15–20 秒至少换一次“类型”**：图 → 结构 → 图 → 文字，不要连着三张图卡。
3. **一条片子至少用 6 种版式**；有流程就用 `flow`，有对比就用 `compare`/`bars`，
   有“谁说了什么”就用 `chat`，有提交/日志就用 `terminal`——这些信息用 `card` + 大字讲，等于把视频做成 PPT。
4. **结构版式的 `big` 要更短**（3–6 字）：下面已经有面板/条/列表，大字再长就顶到面板上。
5. **`extras` 里的字是画面字，不是口播**：每条控制在 18 字以内，超过会被自动截断成 `…`。

`extras` 各版式的完整字段：

| 版式 | extras |
|---|---|
| `chat` | `{"title","badge","msgs":[{"who","role":"user\|agent","text","tag"}]}` |
| `layers` | `{"top":{"label","sub","chips":[]},"bottom":[{"label","lines":[]}],"note"}` |
| `flow` | `{"steps":[{"t","s"}],"note"}`（3–5 步） |
| `compare` | `{"left":{"kicker","title","items":[]},"right":{…},"vs":"VS"}`（每边 ≤4 条） |
| `bars` | `{"rows":[{"label","value","text","strong"}],"max","note"}`（≤3 行） |
| `kpi` | `{"items":[{"v":"300","u":"条消息","l":"模拟环境"}],"note"}`（2–3 个） |
| `list` | `{"items":[{"k":"连续","d":"跨群聊和 PR 保持上下文"}],"note"}`（2–5 条） |
| `terminal` | `{"title","lines":[{"k":"add\|del\|ctx\|meta","t"}],"status","note"}`（≤9 行） |
| `quote` | `{"text","by"}`（`big` 留空，整块引语占满大字区） |
| `diptych` | `{"left":{"img","label"},"right":{"img","label"},"note"}`（两张图按同高并排） |

长句、表情符号、链接不要塞进 `extras`；那里是**画面**，观众只会扫一眼。


## 阶段 2 — 配音

有 VoxCPM2 就用。注意：实际安装的 CLI/API 可能比 GitHub README 旧，先看真实签名再传 `seed`（2.0.3 包不接受 `seed`，用 `torch.manual_seed`）。核心 API：

```python
model.tts_model.build_prompt_cache(...)
model.tts_model.generate_with_prompt_cache(
    target_text=..., prompt_cache=..., inference_timesteps=10)
```

### 默认音色：q1（女声，已内置）

`scripts/voices/q1/` 打包了一套现成音色：prompt 5.7 秒 + reference 14 秒，都是**去掉背景音乐后的干净人声**（prompt 基频中位数约 239Hz，自然语速约 6.6 字/秒）。脚手架把 `voices/` 拷进项目后，`tts_chunks.py` 默认就用它，不必再准备 `audio/prompt_ref.wav`。

- 参数都在 `voices/q1/voice.json`：`prompt_text`（prompt 的准确文本，必需）、`atempo`（0.92，把偏快的语速压到 5.7–6.1 字/秒）、切片区间与来源。
- 项目里放了 `audio/prompt_ref.wav` 时以项目为准（自定义音色优先）；也可用 `VOICE=<name>` 选 `voices/<name>`。
- **换音色**：`python make_voice_ref.py --src ../../02/q1.mp4 --prompt 8.66,14.32 --ref 8.66,22.72 --transcribe` 先打印词级时间戳，挑好边界（落在词的起止，不切在字中间）后去掉 `--transcribe` 重跑，会生成 `voices/<name>/`（含 `voice.json`）。
- **参考音频带 BGM 时必须先去噪**：`make_voice_ref.py` 已内置 ZIP-Enhancer；直接拿带伴奏的原片克隆，会把底噪和音乐一起学走。
- **验收音色**：`python check_voice.py` —— 每段基频落在参考 ±18% 内、段间极差 ≤30Hz、与参考的 LTAS 相关 ≥0.90、语速 4.5–6.5 字/秒。听不出差别时就看这几个数；实测 q1 四段：基频 225–251Hz（参考 239Hz）、LTAS 0.978–0.990、语速 5.7–6.1。

### 环境

系统 Python 常常是 CPU 版 torch。有 CUDA 时，建一个继承已安装 `voxcpm` 的隔离 venv，只补 CUDA torch：

```bash
python -m venv --system-site-packages .venv-tts
.venv-tts/Scripts/python.exe -m pip install --no-deps \
  torch==2.11.0+cu128 torchaudio==2.11.0+cu128 \
  -f https://mirror.sjtu.edu.cn/pytorch-wheels/cu128/
```

默认 PyTorch 源可能很慢；SJTU 镜像实测约 15MB/s。CPU 推理约 40 倍实时（30 秒音频约 20 分钟），工具调用会超时；CUDA 把 3 分钟脚本压到约 5 分钟生成。

### 最重要的一条：长段生成，不要逐句

逐句克隆会让音色漂移。被否的版本里，45 个独立 beat 的基频中位数在 **71–154Hz**；同一 prompt/reference 生成的 4 个长段是 **100 / 103 / 100 / 98Hz**。不要为了“时间精确”逐句生成；时间精确靠后面的 ASR。

1. 用 **4–8 秒 prompt + 更长的 reference**（同一音色）：文本必须已知，写进 `voice.json` 的 `prompt_text`；prompt + reference 比只用 reference 稳。
2. 生成 **2–4 个长段**，每段 30–60 秒，每 2 个场景一段。同一 prompt cache、`torch.manual_seed(20)`、`cfg_value=2.0`、`inference_timesteps=10`。
3. 不要给每段加风格前缀，除非确有必要；风格提示会改变音高。整体偏快就统一做 `atempo`（`voice.json` 的 `atempo` 会自动应用，原始段存 `*_raw.wav`）。
4. 每段测量：基频中位数（librosa.pyin，60–350Hz）+ 字/秒 + 与参考的 LTAS 相关。**重点是段间稳定、与参考同音区**，不要硬套 85–115Hz（女声的 q1 在 225–251Hz 才是对的）；语速 4.5–6.5 字/秒。
5. 跑 `check_voice.py`，PASS 再往下走；不合格先换参考片段/重生成该段，不要用变调硬拉。
6. 长段保留，后面绝不再切。

命令：`scripts/tts_chunks.py`，分别跑 `--part 0 --of 2` 和 `--part 1 --of 2`。生成完先挑种子、再清理、再验音色：

```bash
python regen_chunk2.py --seeds 20,21,22,23   # 每段 4 次；按参考音 f0/LTAS 挑，候选落 audio/cand/
python clean_audio.py                        # 按 TEMPO_MAP 逐段 atempo（一次到位）+ 去瞬态 + 压停顿
python check_voice.py --baseline ../../work/<上一版>/audio   # 与上一版比 MFCC（硬）/Δf0（参考）
```

`check_voice.py` 的门禁是**参考音 ±8%、段间极差 ≤18Hz、MFCC ≥0.985**（旧版是 ±18% / ≤30Hz）。
实测同一批生成 4 段能拿到 262/251/250/239Hz；262Hz 只比参考高 10%，旧门禁放过，但听感就是
“开头换了个人”。`regen_chunk2.py` 换种子重挑后收到 240/237/246/240Hz —— 同一段文本、同一参考，
只换采样种子，音色就能差这么多，所以**不要省这一步**。

`clean_audio.py` 很关键：VoxCPM2 每段开头有 40ms 的 −11dB 瞬态，后面还跟着 0.3–0.4s 静音；
段落拼接点又正好落在章节开头，不清掉就会出现“**每节开头咔一下、停半拍**”。

## 阶段 3 — 连续音频与混音

1. 每段只裁首尾静音（−45dB 阈值，80ms 余量），段间留 **0.45 秒**空白（句内停顿已被 `clean_audio.py` 压到 ≤0.45，这里再长就会显停顿）。**不要按 beat 加空隙，也不要按 beat 切。**
   注意 `trim()` 两端各留 0.08s pad：`CHUNK_GAP=0.65` 实测拼出来是 0.68–0.78 秒，
   正好被 `check_audio.py` 的“最长停顿 ≤0.65s”判 FAIL（v7 起默认 0.45，实测 0.54–0.62s）。
2. 48kHz 生成 `narration.wav`、`music.wav`、`sfx.wav`。
3. 混音：口播 `loudnorm=I=-16:TP=-1.5:LRA=11`；音乐约 −38dBFS RMS；音效峰值约 0.30；`amix` 后加 `alimiter=limit=0.95`。
4. 检查分轨：口播 RMS 约 0.13，音乐约 0.010，音效约 0.005，最终真峰值 ≤ −1.5dB。第一版音效峰值到 1.0 直接削波，限幅器修掉了。
5. 音效：场景起点 whoosh、3–4 个重点 beat 用 impact、数字用 tick、反转前一个 riser。要稀疏；每 3 秒一个 whoosh 就成噪音了。**开头 0–1 秒不要放 impact/whoosh**：音乐还在淡入，噪声冲击叠上去就是一声“刺啦”。

对应脚本：`scripts/build_audio_cont.py` + `scripts/build_audio_utils.py`。

## 阶段 4 — ASR 对齐（修“话没说完就切”）

画面/字幕切换必须落在**下一句开口**，且上一句已经完整播完。

1. 用 faster-whisper（`small`，CPU `int8` 足够）转写每个长段。**先把 48kHz 重采样到 16kHz**；直接喂 48kHz 会让 Whisper 听到 3 倍慢速音频，输出英文幻觉。
2. 取词级时间戳：`word_timestamps=True`、`language="zh"`。
3. 归一化原文和转写（去标点/空格、转小写），用 `difflib.SequenceMatcher` 做字符匹配；记录每个 beat 匹配到的第一个转写字符。
4. 第 *i* 个 beat 的结束边界 = **第 *i+1* 个 beat 第一个匹配词的开始时间**。最后一个 beat 到段尾结束。
5. ASR 失败时，回退到按字数比例的时间，并**偏晚**，绝不偏早。偏晚只是画面多停一拍；偏早就是切掉句子。
6. 写出 `asr_times.json`，用它构建时间轴。抽三个点验证：A 句最后词结束、停顿、B 句第一个词开始；切点必须等于 B 的开口。
7. **ASR 词起点偏早时，往后吸到“停顿结束”。** whisper 的中文词起点常早 0.3–0.9 秒，切点会落进上一句的尾音里。`build_audio_cont.snap_forward_to_pause` 的做法：找到切点之后那段静音（≥0.12s），把切点放到静音结束 +0.03s；**只往后、最多 1 秒**，已经落在开口上的切点不动。实测一条 1.66 秒的镜头，原本在句中切，挪到停顿后变成 2.5 秒，尾音保住了。
8. **章节边界 = 新章节第一句的开口，不要取两段中点。** 长段之间还有 0.65 秒空白，取中点会让章节标签/进度条在开口前 0.3–0.4 秒就跳，`check_audio.py` 的 ±0.15s 会判失败。
9. **中文数字被转写成阿拉伯数字时，切点会落进句中。** “六千零七” → `6007`、“五千五百八十九” → `5589`，
   `difflib` 会跳过这几段，把切点对到后面的英文词（实测对到 `Claude`，晚 1.3 秒，上一句字幕停在画面上）。
   跑 `python fix_boundaries.py`：只问“切点是否落在静音里”，落在语音里就挪到最近的静音结束（≤1.5s）；
   **不要按字数估**——`14 万行 Fortran`、`±10⁻¹⁰ K` 这种英数混排会估歪，实测把正确的切点推后 1.7 秒。
   改完跑 `check_audio.py`，并抽这几个点确认上一句已经完整播完（必要时看 0.1s 能量包络）。

10. **同音字会把切点带偏，改用拼音匹配（`align_asr2.py`）。** 实测 Whisper 把“每俯冲一次”写成“没辅充一次”，
    `difflib` 找不到“每/俯/冲”，把这个 beat 的第一个匹配字落到后面的“一次”上，切点晚 0.8 秒，
    那一镜只剩 1.63 秒（算出来 8 字/秒，物理上不可能）。`align_asr2.py` 把原文和转写都转成
    **不带声调的拼音**（`pypinyin`）再匹配，数字先转中文读法（“0.3”→“零点三”），切点回到 12.28 秒，
    经 `snap_to_onsets` 吸到真实开口 12.62。**新项目默认用它**，`fix_boundaries.py` 只作兜底。

11. **先看“每个 beat 的字/秒”这张表，别急着往下走。** `align_asr2.py` 会打印
    `chunk i: N beats c/s a b c ...`；正常是 **4.0–7.0**。出现 0.45 秒（40+ 字/秒）或 10+ 字/秒，
    就是切点错了，不是语速问题。实测一轮踩到 4 个 beat 被压成 0.45 秒、下一镜吃掉 7–8 秒，三种原因：
    - **只认第一个字**：第一个字落在匹配块边界外（同音字/漏字）就退回 `+0.45s` 等距估计。
      修法：在本 beat 的**字范围内**找第一个真正匹配上的字（`align_asr2.py` v7 已内置）。
    - **整词拼音**：`heard_units()` 对整词取拼音，`Scout` 变成单音节 `"Scout"`，和逐字的 `s/c/o/u/t`
      永远不匹配 → 那一句切点整体后跳 1 秒。修法：逐字取拼音并小写。
    - **中文数字被念成、又被听成另一串**：`80/90` 被 Whisper 写成“80片支8”，`difflib` 整段跳过。
      这类只能**人工按 Whisper 的分段起点**改一个值（`asr_times.json` 里改一处，再重跑 `build_audio_cont.py`），
      改完 `check_audio.py` 的开口对齐必须 ≤0.15s。
12. **`num_cn()` 递归别传 int。** `n % 100` / `n % 1000` 出来的余数被再次传进去时若还是 int，
    遇到含百/千的数字直接 `TypeError: argument of type 'int' is not iterable`（v7 已修）。

脚本：`scripts/align_asr2.py`（首选，拼音）→ `scripts/align_asr.py`（原始字符匹配）→ `scripts/fix_boundaries.py`（静音兜底）。实测：“它连轴转了十一天”在 7.5–9.0 秒播完，9.0–9.5 秒停顿，切点 9.54 秒正好是下一句开口。早先逐句切只给了这句 1.08 秒，尾音被切掉。

## 阶段 5 — 渲染

手机默认：1080×1920，30fps，H.264 High，AAC-LC 48kHz 立体声，CRF 18–20，`-preset veryfast`，`+faststart`。

竖屏版式：

- 顶部 4–6px 进度条；左上章节标签在 y≈75；右上小品牌名。
- 大字区在 y≈220–500：eyebrow 27px，主关键词 90–170px（自动缩到 960px 宽），下划线用 `textbbox`。
- 图片卡：全宽 1080×608，y≈540；同一张图做模糊、压暗后铺满 1920 背景。
  卡片内图片按比例 **contain**（16:9 正好铺满；竖图两侧用同一张图模糊压暗填底），不拉变形、不裁掉图上说明文字。
- **视频卡分五种**：横素材 `card`（1080×608）、高位 `full`（1080×760，y=470）、竖素材 `phone`
  （整帧进设备卡，**不缩放不裁切**）、前后对照 `diptych`（两张抽帧并排 + 标签）、
  **`text`/`quote`/`data` 的满幅窗口**（1080×764 铺在 y=470–1234，文字在上）。见「视频 + 文字」一节。
- **大字的位置和字号由 `layout_text_box(b)` 一处决定**（字号起点、基线、下划线允许的最低 y）：
  `card/hook` 268/512、`full` 236/442、`phone|diptych` 232/442、结构版式 262/`STAGE_TOP-28`、
  `text+窗口` 172/`WIN_Y-28`。`fit_text_in_box()` 再按真实字形 bbox 收字号，
  保证 `textbbox()[3] + 16 ≤ 卡片顶边 − 28`。**不要在任何地方再写死 200px。**
- 结构版式的舞台区在 y≈536–1180，占满图片卡的位置；同样是“大字在上、面板在下”的层级，
  所以切换时眼睛不用重新找位置。默认深色渐变底；**给了片段就走模糊动态底**（`clip_bg_fill`），
  没片段才用纯色——纯色文字卡一条片子别超过 20%（规则 30）。
- 字幕：64px 加粗，最多 2 行，居中在 y≈1400–1550，黑色描边 8px，后面加暗色 scrim。
- 安全区：左右留 60px；避开底部 250px、右侧 120px 的平台 UI。

结构版式的实现要点（`render.py` 里的 `STAGE_DRAW`）：

- 每个版式**自带分段入场**：气泡一条条出、架构先上后下、流程一步步亮、条形一根根长、数字 count-up。
  这不是装饰——它让“这句话讲了几件事”变成可见的节奏，观众能提前知道还剩几条。
- 入场动画全程 `lt / duration` 驱动，**不做循环、不做闪烁**；镜头整体仍有 2.2% 缓慢推近 + 光扫，
  防止编码器把静止区域判成冻结帧。
- 所有文字走 `ellip()` / `fit_lines()` 截断，**任何 `extras` 都不许把字顶出安全区**；
  中文换行走 `wrap_cjk()`（不让行首落在“，。”上）。
- `terminal` 的窗口高度跟着 diff 行数走；行少就不要留一大块空面板。
- `quote` 不按单行缩字号：按“最多 3 行 + 末行不是孤零零的标点”反推字号，没有 `big` 时整块占满大字区。
- `chat` 每条消息上方要留 34px 名字行，舞台起点比标题条再低 40px，否则名字会被标题条压住。

运动规则：

- **线性、无 clamp 的 Ken Burns**，覆盖包含停顿的整个镜头：`prog = min(1, lt / (next_start - start))`。不要用 smoothstep，它首尾速度为 0，会制造停顿。
- **按 beat 计，不按场景计。** 场景有 8–10 个 beat、20–30 秒，`prog` 摊到整场后每帧只变 0.0001，等于静止画面；按 beat 计时，每个镜头 3%–5% 推近，切镜头时重置（重置被硬切掩盖，看不出来）。
- 亚像素采样：`Image.transform(..., Image.AFFINE, ...)`，用浮点缩放/位移。整数 `crop().resize()` 会每隔几帧跳 1px，产生微抖。
- **硬切，不叠化。** 叠化会让两行大字双重曝光，看起来像故障。切点用 whoosh 盖住。
- 文字/数据卡：整个画面缓慢推近（每场景约 7.5%）+ 低透明度光扫。否则编码器会跳过相同帧，卡片就冻住了。
- **动态片段镜头**：`idx = lt / duration * frames` 按 beat 进度取帧，不循环、不冻结；
  这些镜头跳过整帧 `slow_zoom`，免得把画面边缘（水印、手）裁掉。
- **底图压暗按亮度自适应**：`alpha = clamp(150 + (mean − 55) × 1.15, 150, 215)`。
  白底照片用固定 150 会整屏发灰，标题和字幕都没对比。
- **数据卡 count-up 压到 0.55 秒**：1.1 秒的动画放在 1.18 秒的镜头上，观众几乎整段看到“0.3 克”。
- **标题卡装饰数字按长度自动缩**：`getlength > 640` 就减字号；230px 的 “0.5g” 会贴右边缘被裁。
- **结尾卡从 `speech_end` 触发**：`build_audio_cont` 把最后一个 beat 的 end 设成总时长，
  用 `last["end"]` 判断等于永远不会出现。
- 不要在每次切换做 punch-in，也不要白闪；这两个都会放大“顿一下”的感觉。
- 下划线一律按字形 bbox 下移 12–16px，大字和 27–32px 的小标签都是：

  ```python
  EYE_GAP = 13

  def draw_eyebrow(d, x, y, text, size, color, ac, gap=EYE_GAP, upper=False):
      t = text.upper() if upper else text
      f = font(size, False)
      d.text((x, y), t, font=f, fill=color)
      bb = d.textbbox((x, y), t, font=f)     # 墨迹下缘，不是 y+字号
      ly = bb[3] + gap
      d.rectangle([x, ly, x + 36, ly + 4], fill=ac)
  ```

  卡片的 eyebrow 在 y≈214（27px）、文字卡在 y≈600（28px）、数据卡在 `top`（32px），
  三处都要走这个函数；数据卡的 `eye_h` 要跟着从 48 加到 60，否则线和数字挤在一起。

- 纯文字版式：底图偏亮时加暗色 scrim；压暗量按底图平均亮度算，深色底图不要硬加（会发灰）。
- 字体用 `C:\Windows\Fonts` 下的 `Noto Sans SC Bold` / `Medium`，传完整 `.otf` 路径（含空格）。

**配图规则（本轮返工两次）：**

- 逐句判断，只在这句话和图片内容真的对得上时才配图（`script_data.py` 每个 beat 的第 7 位单独指定，`None` 表示不用图）。
- 原文配图通常自带中文标题（“资本流向，决定岗位边界”“工具贬值快于人成长”）；如果图上文字和这句语义相反，就不要配这张图（例：讲“过去能顶四五年”却配“工具贬值快”）。
- 一个 30 多镜头的视频，**一半有图、一半是数据/文字卡**是正常的；宁可少配图，也不要每场景套同一张默认图。
- 配图没法自动判语义，但可以自动拼图：`python contact_sheet.py --video out/xxx.mp4` 生成 `out/配图对照.png`，一眼扫完 30 多个镜头。
- **空白边按 `image_margins.py` 的建议处理**（阶段 0 第 3 步那张表）。裁剪过的图放 `assets/`，beat 里写衍生文件名即可。
- `poster` 版式是给“竖构图/近方形插画”的：卡片按图收窄（1080 宽里约 580×800），图顶到卡片四边，
  留白交给深色背景。注意三点：① 卡片不要贴字幕——`y+h` 到字幕区（约 1440）留 ≥100px；
  ② 不要给 `poster` 卡加上方强调条，它离大标题下划线只有十几像素，会看成“两条线”；
  ③ 同屏其他用图镜头仍是 16:9 宽卡，一张竖卡正好在收尾/转折处换节奏，别连着用两张。
- 超宽横幅（4:1）走 `image_card` 的深色卡底分支后，图上下会各留一条深色；这是刻意的，
  比“同图放大 2.2 倍模糊填空”干净得多——后者会把白底上的彩色装饰拉成刺眼色块。

`scripts/render.py` 是可直接用的竖屏渲染器。首次渲染前改项目副本里的 `BRAND`、`TITLE_MAIN`、`TITLE_SUB`、`TITLE_KICKER`、`TITLE_CREDIT`、`END_L1/L2/Q/CTA/SOURCE`、`DATA_SOURCE`，或设置对应的 `VIDEO_*` 环境变量；开场第一句就是钩子/原声时设 `VIDEO_NO_TITLE=1` 跳过那 1 秒标题卡。不要带着示例品牌名出片。

## 阶段 6 — QA 与交付

自动检查（`scripts/qa_video.py`）：

- `python check_text_gap.py`：大字/下划线有没有压到卡片或面板（逐 beat 复算字形 bbox，<12px 判 FAIL）。
- 数一遍“有运动原片的镜头数 / 总镜头数”，纯色文字卡要 ≤20%（本片 34/40、纯色 4 个）。

`qa_video.py`：

- `ffprobe`：时长、1080×1920、30/1、H.264/AAC。
- PTS 间隔：每个 `1/30` 秒，无重复时间戳；`-f null -` 完整解码无错误。
- 帧差：在 3–5 个已知切点附近解码取帧，**帧差要 0–1 归一化**；连续 ≥3 帧完全相同（diff = 0）才判冻结。慢推拉每帧只差 0.00005 是正常的，不要用 0.02 这种阈值把慢镜头判死。
- 音频：`ebur128=peak=true`，整体约 −16 LUFS，真峰值 ≤ −1.0dB（目标 −1.5）。

人工抽查：

- 只看前 20 秒：能否说出突破点和接下来要回答的三个问题？章节标题用“所以/但是”连起来是否成句？
- 看钩子、切点、文字卡、下划线修正、结尾卡这几帧。
- 在 2–3 个边界对照字幕和语音；上一句字幕必须保留到下一句开口。
- 听一遍边界附近，确认没有丢字。
- 有动态片段时，每个片段抽两帧确认内容与运动，并确认没有混进原片人声。
- 确认旧版本还在，README 里有链接。

### 发布文案怎么给（视频号 / 抖音通用）

视频不是交给用户就完了——**观众看到的第一屏是封面和标题，不是视频**。所以每次出片都按
`scripts/publish_copy_template.md` 填一份 `out/发布文案.md`，五项齐：

**短标题的字符是平台定的，不是审美问题。** 视频号 / 抖音只认下面这些符号，其余一律判
“含特殊字符”，标题过不了、整条片子白发：

| 允许 | 写法 | 例子 |
|---|---|---|
| 书名号 | 《》 | 《Super Agent 设计》 |
| 引号 | “”‘’ | AI 最狠的设计是“少说话” |
| 冒号 | ：: | 最狠的设计：少说话 |
| 加号 | + | 29+15 |
| 问号 | ？? | 你希望群里出现吗？ |
| 百分号 | %％ | 快了一倍 40% |
| 摄氏度 | ℃ | 机房 35℃ |
| 逗号 | **换成空格** | 群里没人叫它 它自己修好了Bug |

`@ # 顿号、分号、感叹号、括号、破折号、斜杠、小数点、英文连字符` 都不在白名单
（`Super-agent` 写成 `Super Agent`）。实测：
“群里没人@它，它把Bug修了”会被拒（`@` + 逗号），改成“群里没人叫它 它把Bug修了”；
“29.5 分钟”也不要用，写“29 分钟”或“半小时”。出片前跑门禁：

```bash
python check_title.py --file out/发布文案.md     # 不过就改到过，退出码非 0 会拦在发布前
```

1. **短标题 3 个**（列表页展示，**≤16 字**，别用整句长标题，且必须过上面的字符白名单）：
   主推 = 数字 + 提问/反差；备选 = 最短的反差句；备选 = 悬念式。
   标题里的数字口径必须和封面、开头第一句一致（标题写“四成”，封面就不能写“40%”，反之亦然）。
2. **摘要 2 版**：只差**人群切入口**（家长向 / HR 向、消费者向 / 从业者向），
   正文数字与结论必须完全一致，不能出现互相矛盾的口径。
3. **摘要第一行就是钩子**：前 40 字左右是不点“展开”就能看到的部分。
   不要用“本期视频聊聊…”“大家好”开场；第一行放最反直觉的那个数字。
4. **话题 4–6 个**，三类各占：大词（曝光）、垂类（精准）、人群（共鸣）。
   堆到 10 个只会稀释曝光，还像营销号。
5. **置顶评论**：把主题句写成一句可带走的话 + 一个**二选一**问题（“你更担心 A 还是 B？”），
   比“你怎么看”更容易起量。
6. **封面**：`python make_cover.py` 从成片抽钩子镜头那一帧（默认第 0 个 beat +2s），
   输出 1080×1920；**不要用 0–1 秒的标题卡**——缩略图里那只有几个字，看不出主题。
   平台若要别的比例（如 6:7 分享卡），`--ratios 6:7 --offset 0.22`，裁完必须看一眼有没有把字幕切半。

## 排错表

| 现象 | 根因 | 修法 |
|---|---|---|
| 每隔几句音色就变 | 逐句克隆重新采样说话人 | 改 2–4 个长段；同 prompt + reference；测段基频 |
| 克隆出来带底噪/伴奏 | 参考音频本身有 BGM | 先过 ZIP-Enhancer 去噪（`make_voice_ref.py`） |
| 音色“说不清哪里不对” | 没量化，参考片段切在字中间 | `check_voice.py` 看段间基频极差与 LTAS；按词边界重切 |
| 语速太快/不可信 | 7–8 字/秒、基频高 | 低音平稳 prompt，5.2–5.8 字/秒；个别句轻微 atempo，不要变调 |
| 丢字/话没说完 | 按估算停顿逐句切音频 | 长段整体保留；ASR 对齐；绝不切 |
| 字幕抢在句尾前切换 | 用停顿中点或按字数比例 | 用 ASR 的“下一 beat 第一个词”起点 |
| 图片切换卡顿 | 停顿期间推拉被 clamp；静止后跳；叠化 | 全镜头线性运动、不 clamp；硬切；文字卡推近+光扫 |
| 慢推拉微抖 | 整数裁切跳步 | 仿射亚像素变换 |
| 文字卡像冻住 | 只有静止文字，编码器跳过块 | 整帧缓慢推近 + 光扫 |
| 下划线压字 | 线画在 `y+font_size` | `textbbox()[3] + margin` |
| 小标签的下划线贴着字（差 2–4px 发脏） | 写死 `top+42`，而 32px 墨迹下缘正好是 `top+42` | eyebrow 统一走 `draw_eyebrow()`，`textbbox()[3] + 13`；数据卡 `eye_h` 48→60 |

| 字体豆腐块 | WSL 没有中文字体 | 用 Windows Python + `C:\Windows\Fonts\NotoSansSC...` |
| 图片链接全坏 | MD 指向 `assets/...` | 按文章顺序映射，逐张看图，修 `img` |
| 开头“刺啦”一声 | 音乐淡入期叠了 impact/whoosh | 第一秒不放音效；转场 whoosh 降到 0.45 |

| 竖屏素材“显示不全”“高度丢了” | 600×800 的手机录屏被裁成 600×337 塞 16:9 卡片 | 换 `phone` 版式整帧进设备卡，`CLIP_SIZE` 给竖尺寸；16:9 片段也别为铺满去裁 |
| 片段里“半行字被切掉” | 裁切坐标按肉眼估，落在文字行中间 | 按暗行测文字行位置（见阶段 0），裁到行与行之间，留 10–20px |
| 大字压在卡片上 / 标签被盖住 | `phone`/`full`/`diptych` 的卡片从 y≈470 起，而大字基准线还是 292/200px | 这三种版式大字缩到 150px、基准线 240/262（`render.py` 已内置） |
| 讲完能力不知道它怎么赚钱 | 漏掉定价：免费层给什么、付费层卖什么 | 商业模型单独一章（`compare` 免费 vs 付费 + `data` 首月收入）；价格必须进片 |
| 第一层“很厉害”但观众记不住 | 只有形容词，没有画面证据 | 第一层每小节配一个能看见的镜头（变装、换色、改比例、免费下载） |
| 只有一个音色段跑偏，改另一段反而更差 | 换种子重挑后段间极差仍差 0.4Hz 卡在门槛上 | 先把跑偏那段重挑；还差就再重挑另一个偏离段（实测 254→241 后极差从 18.4 降到 6.9Hz） |
| `fix_boundaries` 把切点往更晚处挪，句子被切短 | 中文数字被转成阿拉伯数字，`difflib` 跳过，静音判据落在句中的微小停顿上 | 不要盲信 `fix_boundaries`：按 ASR **段落起点**人工核一遍，再只做 `snap_to_onsets(tol=0.30)` 轻吸附 |

## 完成标准

- [ ] **文章地址用 `article_prep.py` 过了一遍**：图片全部落地到 `assets/`、缺失图 0 个、
      字数与时长预估看过、`out/article_digest.md` 里每个数字都对过口径。
- [ ] `run_env.sh` 里 `VIDEO_*` 已登记进 `WSLENV`，抽帧确认品牌名/结尾卡是本文案（不是示例）。
- [ ] 每张图都映射并目检过（顺手记下图上自带的中文，避免和大字重复）。
- [ ] 每张图都量过空白边（`image_margins.py`）；该裁的裁成 `assets/` 衍生图，`poster` 卡不贴字幕、没有“两条线”。
- [ ] **0–3 秒有画面 + 一句结论**（不是标题卡、不是背景介绍）；前 20 秒走完四拍（炸点 → 炸点 → 判断 → 路线图）。
- [ ] 第一帧抽出来给同事看：他能不能说出“这片子讲什么、为什么值得继续看”。
- [ ] 有一句写下来的**突破点**（不是主题句）：反常识、有代价、观众会因此改变一个判断，25 字内能说完，且已写进 `script_data.THESIS`。
- [ ] 三个小标题用“所以 / 但是”能串成一条因果链，不是三个并列话题；换题测试不成立（结构是这篇独有的）；答不上“它证明了突破点的哪一半”的素材已砍掉或压成一个镜头。
- [ ] 人物/产品类文章是**两层次**：第一层每个小节都有画面证据，第二层每个小节都有机制（生成 → 评估 → 定价），价格进了片。
- [ ] 35–50 个 beat；总长 2:15–3:30（单点讲透 2:15–3:00 正常；用户明确要 5 分钟时按比例放宽到 60–70 个 beat / 4:30–5:00，且只围绕一个突破点）；字幕每行 ≤ 15 个中文字。
- [ ] 2–4 个长段配音；段间基频极差 ≤18Hz 且落在参考 ±8%；4.5–6.5 字/秒；`check_voice.py` PASS。
- [ ] 与上一版对比过：`check_voice.py --baseline 上一版/audio` 通过（MFCC ≥0.99；Δf0 >15Hz 会 WARN，听一下语气）。
- [ ] 每段只做一次 atempo（`TEMPO_MAP`），没有 <0.80 的减速；没有叠两次。
- [ ] `fix_boundaries.py` 跑过；中文数字那几句的切点落在开口上，上一句完整播完。
- [ ] 音频连续，没有按 beat 切；切点经 ASR 对齐。
- [ ] 无叠化；每个镜头都在动；亚像素推拉；下划线用 bbox，大字和小标签都留 12–16px 空隙。
- [ ] **版式轮换达标**：≥8 种版式（有视频素材时至少用上 `card` + `phone`，有前后对比再加 `diptych`）、同版式不连续、`text` ≤20%、每 15–20 秒换一次类型；结构版式的字没有顶出安全区、没有被截成半句。
- [ ] **纯色文字卡 ≤20%**，其余文字/引语/数据镜头都垫了画面（满幅窗口或模糊动态底）；数一遍“有运动原片的镜头数 / 总镜头数”，本片 34/40。
      **没有原片时换算法**：纯色底只剩 `data` 卡，其余靠 `img` 模糊底撑（实测 2/47 = 4%）。

- [ ] 第一帧不是标题卡（`VIDEO_NO_TITLE=1`；`render.py` 在标题卡开启时会打 warn）。
- [ ] **竖屏/竖构图片段走 `phone` 整帧**，没有被裁掉高度；`phone`/`full`/`diptych` 的大字没有压到卡片或标签上。

## 脚本

复制到项目里、和 `script_data.py` 放在一起；`voices/` 也要一起拷（内置 q1 音色）。默认假设 `audio/chunk_0..N.wav`、`out/`、Windows Python/ffmpeg；音色优先用 `audio/prompt_ref.wav`，没有就用 `voices/<VOICE>/`。

- `scripts/tts_chunks.py` — VoxCPM2 长段配音（默认 q1 音色，自动套用 `voice.json` 的 atempo）。
- `scripts/clean_audio.py` — 逐段 atempo（`TEMPO_MAP`，从 raw 一次到位；没有 raw 时 WARN 会叠加）、去段首瞬态、压缩长停顿（修“每节卡一下”）。
- `scripts/regen_chunk2.py` — **音色漂移主力**：每段按 4 个种子生成，候选落 `audio/cand/`，按参考音 f0/LTAS 挑最像的一次。
- `scripts/regen_chunk.py` — 老版单段重生成（保留兼容，参数写死目标 243Hz）。
- `scripts/make_voice_ref.py` — 从视频/音频抽音色：词级时间戳 → 切片 → 去伴奏 → `voices/<name>/`。
- `scripts/check_voice.py` — 量段基频/LTAS/MFCC/语速；门禁参考音 ±8%、段间 ≤18Hz；`--baseline 上一版/audio` 对比系列音色；TEMPO<0.80 会 WARN。
- `scripts/align_asr.py` — 16kHz faster-whisper 词级对齐 → `asr_times.json`。
- `scripts/fix_boundaries.py` — 只用静音判据修切点（中文数字被转写错时用），`--dry` 先看会改哪几处。
- `scripts/build_audio_utils.py` — 垫乐、音效、混音、SRT、解说稿。
- `scripts/build_audio_cont.py` — 连续音频 + 分轨 + `timeline.json`；切点吸附到开口。
- `scripts/make_cover.py` — 从成片抽钩子镜头做封面（1080×1920），可加 `--ratios 6:7` 出分享卡比例。
- `scripts/publish_copy_template.md` — 发布文案模板：短标题 / 摘要 / 话题 / 置顶评论 / 自检表。
- `scripts/check_title.py` — 短标题字符门禁：平台只认书名号/引号/冒号/加号/问号/百分号/摄氏度，逗号换空格；超 16 字、含 `@` 等直接 FAIL。
- `scripts/image_margins.py` — 量配图空白边（四角色/alpha → 墨迹 bbox），按内容占比建议 `card` / `poster` / 不裁，可 `--crop` 生成 `assets/` 衍生图。
- `scripts/render.py` — 竖屏渲染器（静帧推近 + 动态 B-roll + 自适应压暗 + 下划线修复 + `poster` 竖卡 + `cover` 整屏 + **`phone` 设备卡（竖屏整帧不裁）** + **`diptych` 前后对照** + 超宽横幅深色卡底 + **文字类版式的满幅视频窗口 `clip_window`** + **图表版式的模糊动态底 `clip_bg_fill`** + `assets/` 回落；9 种结构版式 `chat`/`layers`/`flow`/`compare`/`bars`/`kpi`/`list`/`terminal`/`quote`，数据走 beat 的 `extras`；大字几何由 `layout_text_box()` / `fit_text_in_box()` 统一决定）。
- `scripts/check_text_gap.py` — 大字压没压画面：逐 beat 复算字形 bbox 与卡片顶边，间距 <12px 判 FAIL。
- `scripts/article_prep.py` — **文章地址 → 项目**：路径归一（`E:\` ↔ `/mnt/e/`、`%20`、全角引号、UNC）、
  图片解析并复制成 `assets/img01.png`、每张图的内容占比与 `card/poster/裁切` 建议、字数与时长预估、
  按章节的段落/图片/链接/数字摘要 → `out/article_digest.md`。
- `scripts/align_asr2.py` — 拼音词级对齐（同音字不再带偏切点），新项目首选，输出同 `asr_times.json`。
- `scripts/make_clips.py` — 参考视频 → `clips/<beat_id>/` 帧序列（按 beat 时长映射）；`CLIP_FILE` / `CLIP_CROP` / `CLIP_SIZE` 支持两条源片混用、裁竖构图、竖尺寸卡片。
- `scripts/video_sheet.py` — 参考视频逐秒缩略图 + 剪辑点 + 镜头区间。
- `scripts/qa_video.py` — CFR/解码/帧差/响度检查。
- `scripts/check_audio.py` — 声音门禁：开头瞬态/爆音/长停顿/切点对齐/响度。
- `scripts/contact_sheet.py` — 按镜头抽帧拼成 `配图对照.png`，人工核对配图。
- `scripts/project_config.py` — 共享 `EXCLUDE`，可选 `TEMPO` / `TEMPO_MAP`（逐段 atempo）/ `VOICE`。
- `scripts/ffmpeg_path.py` — 自动定位 ffmpeg/ffprobe（避开 WSL 下 `%USERNAME%` 乱码）。

环境变量：`FFMPEG`、`FFPROBE`、`FONT_BOLD`、`FONT_MED`、`ASSET_DIR`（或 `render.py --assets <dir>`；WSL 不会自动透传任意环境变量，除非写进 `WSLENV`）、`VOICE`、`TEMPO`、`PROMPT_WAV`、`REFERENCE_WAV`、`PROMPT_TEXT`、`VOX_MODEL`、`VOX_STEPS`、`VOX_SEED`、`VOX_CFG`、`VIDEO_BRAND`、`VIDEO_TITLE`、`VIDEO_SUBTITLE`、`VIDEO_KICKER`、`VIDEO_CREDIT`、`VIDEO_END_*`、`VIDEO_SOURCE`、`VIDEO_TITLE_GHOST`、`VIDEO_DATA_SOURCE`、`VIDEO_OUT`、`SOURCE_VIDEO`（参考视频路径，优先于 `script_data.VIDEO_SRC`）。

当前故事的音效重点 beat 在 `build_audio_utils.py` 的 `IMPACT_IDS` / `RISER_BEFORE` 里改。
